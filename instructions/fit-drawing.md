# Рисунки итогового фита

Версия: 2026-11-08.1. Корень — каталог с [AGENTS.md](../AGENTS.md).
Читай на этапе оформления результата подбора; для старта численного фита этот
модуль не нужен. Применяется к 1D и 2D вместе с [fit-acceptance](fit-acceptance.md).

<!-- instructions:fit-drawing:begin version=2026-11-08.1 -->

## Общие условия

Каждый итоговый фит сопровождается **`fitdraw_<spectrum_id>.svg`**. Сохраняй его
в каталоге конкретного fit_id; новое уточнение получает новый каталог/версию.
Нужны сохранённые массивы именно текущего фита вместе с экспериментом:
NPZ штатных фитеров содержит оба массива в общем масштабе. Перерисовка не требует
повторного фита или симуляции. Отдельные кривые не нормируй и не меняй их знак.
Перед итоговым ответом открой SVG и оцени читаемость подписей и наложения.

## 1D: эксперимент и фит среза

Из корня проекта, в существующей среде:

```bash
../.mars_env/bin/python src/utils/draw_fit_1d.py \
  --fit "$FIT_NPZ" --spectrum-id "$SPECTRUM_ID" --fit-id "$FIT_ID" \
  --output-dir "$FIT_OUTPUT_DIR"
```

Результат — один график с экспериментом и моделью; по оси поля mT.
`FIT_OUTPUT_DIR` должен существовать, старый рисунок не перезаписывается.

## 2D: шесть кинетик и шесть спектральных срезов

1. Получи шесть канонических полей из полного сохранённого CSV/JSON параметров
   1D либо JSON-снимка/отчёта 2D:

```bash
../.mars_env/bin/python src/utils/canonical_orientations.py --parameters "$PARAMETERS_FILE"
```

Расчёт — резонансы S=1 вдоль X/Y/Z при частоте измерения; это номинальные поля
без уширения, а не гарантированные экстремумы порошковой линии. Для общего
гамильтониана и g, используемых текущими фитерами, квантовые определения в
контекст подгружать не требуется. Проверь покрытие полей измеренной картой.
Агент может задать поля явно: вместо `--parameters` используй
`--fields-T "$B1_T" "$B2_T" "$B3_T" "$B4_T" "$B5_T" "$B6_T"` либо
`--positions "$POSITIONS_JSON"` с шестью `{label, field_T}`. Не называй
произвольное поле каноническим без основания; вырожденные X/Y-поля могут совпадать.

2. Выбери **шесть разных времён** на исходной оси записи, внутри окна подбора.
   По доступной кинетике охвати рост/максимум, спад и поздний участок; недоступные
   этапы не выдумывай. Это решение агента, автоматического выбора времён нет.
3. Построй **один рисунок из 12 панелей**: сверху 6 кинетик в выбранных полях,
   снизу 6 спектральных срезов в выбранные моменты; в каждой панели эксперимент
   и результат 2D-фита:

```bash
../.mars_env/bin/python src/utils/draw_fit_2d.py \
  --fit "$FIT_NPZ" --parameters "$PARAMETERS_FILE" \
  --times-ns "$T1_NS" "$T2_NS" "$T3_NS" "$T4_NS" "$T5_NS" "$T6_NS" \
  --spectrum-id "$SPECTRUM_ID" --fit-id "$FIT_ID" --output-dir "$FIT_OUTPUT_DIR"
```

Времена задаются на **оси эксперимента**, не от начала модели. Скрипт учитывает
`experimental_times_s`/`time_zero_s` и ограничивает сравнение сохранённым fit_mask.
По умолчанию значения между отсчётами интерполируются линейно, без экстраполяции.
Для усреднения по окну добавь `--field-half-width-T` и/или `--time-half-width-ns`:
одно и то же окно применяется к эксперименту и модели, его параметры входят в SVG.
Окна целиком должны лежать в данных и содержать отсчёты.

Для отдельного сохранения выбранных кинетик есть `src/utils/sample_kinetics.py`:
те же `--fit`, `--parameters`/`--positions`/`--fields-T`,
необязательный `--field-half-width-T`, новый `--output "$KINETICS_NPZ"`.
Это необязательный артефакт; отрисовщик сам вызывает модуль сэмплирования.
Массивы в контекст не выводи. Форматы — в [FIT_DRAWING](../src/utils/FIT_DRAWING.md).

## Приёмка

Обязателен `check_fit_draw_1d.py` либо `check_fit_draw_2d.py` из общей папки checks:
код **0**, статус **passed**, новый JSON-отчёт для текущих spectrum_id/fit_id.
Полные команды находятся в критериях готовности [AGENTS.md, §1.3](../AGENTS.md).
Проверяются файл/имя SVG, реальные непустые кривые эксперимента и модели,
состав панелей, идентификаторы и SHA256 текущего FIT_NPZ. Одних осей/легенды
недостаточно; старый рисунок после изменения фита проверку не проходит.
Проверка техническая: качество фита подтверждают отдельные метрики.
Нужны все четыре проверки: шум, доводка, таблица и рисунок. Их результаты,
выбранные поля/времена, окна сэмплирования и путь SVG сохрани в задаче.
