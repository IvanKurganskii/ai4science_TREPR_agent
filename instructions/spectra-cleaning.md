Ссылки на номера разделов относятся к AGENTS.md, если не указано иное.

## 1.1 Очистка спектров и получение срезов в выделенные моменты времени

Очистка спектров считается законченной, когда выполнена проверка:

```
python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/spectra_cleaned.py" "results/spectra"
```
Проверка возвращает 0, если в каталоге лежат дубликаты спетров из папки `data/raw_spectra` проведёной процедурой очистки, описанной в документации; в шапке файлов указаны использованные для очистки методы и их параметры

```
python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/spectra_sliced.py" "results/spectra"
```
Проверка возвращает 0, если в каталоге лежат как минимум по одному срезу для каждого спектра из папки `/results/spectra/processed`; в шапке файлов продублированы детали обработки спектров для 2-х мерных спектров, к которой добавлены промежутки интегрирования, использованные при получении срезов

Обе проверки вернут ошибку, если спектры нулевые (все интенсивности равны 0 одновременно)

Вызови проверку сам перед тем, как дать окончательный ответ. Ответ без пройденной проверки не принимается.

Проверь количества спектров скриптом и сопоставь краткую сводку с условиями.
Шапки проверяй скриптом; в контекст выводи только нужные поля и ошибки в пределах 3.1.

## Порядок очистки

Для каждой подзадачи по очистке спектра:
Режим — конвейер с рассуждениями:
1. выбрать готовый инструмент `src/mars_cleaning` по инструкции ниже; исходники читать только для нужного интерфейса или исправления
2. получить скриптом список файлов, метаданные и краткую сводку данных из `/data/raw_spectra` по правилам 3.1
3. выбрать методы и инструменты очистки
4. провести очистку спектров от постоянных шумов и явных выбросов
5. провести анализ необходимости и возможности применения фильтров
6. запустить фильтры, если возможно.
7. сохранить результаты в папке `/results/spectra/processed`
8. найти максимумы по абсолютной интенсивности сигналов. Проинтегрировать их и сохранить в папке `/results/spectra/slices`
9. найти момент времени, когда форма сигнала перестаёт изменяться во времени. Если новая форма отличается от формы в максимуме и от шума, проинтегрировать, добавить результат в папку `/results/spectra/slices`

## Как использовать `src/mars_cleaning`

Из корня проекта в WSL вызывай модуль через существующую среду и защищённую
оболочку агента. Это локальный CLI; наличие пакета не регистрирует MCP-инструмент.

```bash
../.mars_env/bin/python -m src.mars_cleaning --help
../.mars_env/bin/python -m src.mars_cleaning --request "$CLEAN_REQUEST_JSON" \
  --working-dir "$PWD" --output-dir results/spectra/processed
```

`CLEAN_REQUEST_JSON` — путь к новому JSON-запросу текущей задачи, например в
`results/tables/`. Формат: `{"name":"имя_операции","arguments":{...}}`;
`id` необязателен. Проверяй код завершения и `result.ok` в ответе; при ошибке
читай `result.error`, при успехе — `result.summary`, `result.artifacts`,
метаданные и предупреждения. Успех CLI ещё не означает прохождения проверок 1.1.

| Операция | Когда использовать |
|---|---|
| `inspect_epr_2d` | Список наборов, оси и сводка без записи; `singular_values: 20` добавляет диагностику SVD для выбранного набора |
| `import_epr_2d` | Сохранить выбранный набор в каноническом формате без очистки |
| `correct_epr_2d_baseline` | Вычесть фон и исправить базовую линию по объекту `baseline` |
| `denoise_epr_2d` | Только фильтрация по объекту `denoising` |
| `clean_epr_2d` | Коррекция фона, затем фильтрация; передай хотя бы один из этих этапов |
| `export_epr_2d` | Экспорт без дополнительной обработки |

Во всех операциях `source.path` — путь к CSV, NPZ или поддерживаемому NumPy-PKL.
Для сырого осевого CSV поле в первой строке задано в G, время в первом столбце;
укажи фактический `source.time_unit`, например `ns`. В NPZ ключи `fields_T` и
`times_s` уже означают SI: не переопределяй их единицы. Массив `signal` имеет
порядок `(time, field)`; иной порядок задаётся через `source.layout`. При
нескольких наборах сначала вызови inspect без SVD, затем укажи `source.dataset`.

Минимальный запрос без записи:

```json
{
  "name": "inspect_epr_2d",
  "arguments": {
    "source": {"path": "data/raw_spectra/INPUT.csv", "time_unit": "ns"}
  }
}
```

Пример формы запроса очистки; путь, интервалы и ранг замени значениями,
обоснованными для выбранных данных. Числа примера не задают время лазера.

```json
{
  "name": "clean_epr_2d",
  "arguments": {
    "source": {"path": "data/raw_spectra/INPUT.csv", "time_unit": "ns"},
    "baseline": {
      "field_bounds_T": [0.33, 0.36],
      "time_bounds_s": [0.000001, null],
      "poly_order": 1,
      "baseline_mode": "scaled_reference"
    },
    "denoising": {"method": "svd", "svd_rank": 3},
    "output": {
      "name": "cleaned", "formats": ["npz", "csv"], "time_unit": "ns",
      "save_plot": false, "include_data": false
    }
  }
}
```

`field_bounds_T` и `time_bounds_s` ограничивают **полезный сигнал**: фон
оценивается по точкам вне этих интервалов. Не передавай вместо них границы
самого фонового участка. `null` означает неограниченный конец. Фильтры:
`svd`, `gaussian`, `wavelet`, `median`, `combined`; ранг SVD выбирай по
сингулярным значениям и остаткам. `sigma_t`/`sigma_b` заданы в отсчётах,
`median_kernel` должен быть нечётным. Поля и ограничения — в
[schemas.py](../src/mars_cleaning/schemas.py); примеры — в
[examples/](../src/mars_cleaning/examples/). Не загружай все исходники или
полный `tool_schemas.json` ради выбора одной операции.

Следующий этап запускай с `source.path`, равным фактическому
`result.artifacts.npz` предыдущего: это сохраняет оси SI и историю обработки.
Всегда явно задавай `--output-dir`: умолчание пакета — `results/mars_simulations`.
Имена имеют уникальный суффикс; пути бери из ответа. NPZ содержит `fields_T`,
`times_s`, `signal`, `input_signal`, `removed_signal`, `metadata_json`.
Отдельный JSON сохраняет историю; CSV/PKL экспортируют поле в G и время в
`output.time_unit`. `export_epr_2d` по умолчанию создаёт NPZ и PKL, остальные
операции записи — NPZ. Для CSV укажи `formats` явно.

Экспортируемый CSV содержит числовые оси, но не комментарии, требуемые порядком
сдачи. Перед проверкой дополни **новый выходной CSV** шапкой с источником,
методами и параметрами по сохранённым метаданным; существующие данные не меняй.
Пакет не создаёт временные срезы: получай их отдельным скриптом из сохранённого
2D-измерения, фиксируя родителя, окно, операцию и единицы интегрирования.
Выполни обе внешние проверки 1.1; наличие NPZ/JSON их не заменяет.

Оставляй `include_data: false`; в контекст передавай только сводку, пути и
ошибки в пределах 3.1. Интерфейс Python для составного скрипта:
`from src.mars_cleaning import MarsCleaningTools`, затем
`MarsCleaningTools(output_dir=..., working_dir=...).dispatch(name, arguments)`.
Здесь `ok` находится непосредственно в возвращённом объекте; обёртку
`{"id": ..., "result": ...}` добавляет CLI. `--serve` принимает один такой
JSON-запрос на строку и возвращает один ответ; это не протокол MCP.
