# Фит среза: короткая рабочая инструкция

Версия: 2026-11-09.1. Корень — каталог с [AGENTS.md](../AGENTS.md).
Для подбора готового среза прочитай этот файл; квантовые определения и предметные
темы онтологии подгружай при написании интерпретирующего отчёта.

## Минимальные входы

Используй краткую числовую сводку: частота СВЧ, единицы поля, положения и знаки
разрешённых особенностей, шум, ширины, источник среза и окно времени. Массивы
в контекст не выводи. Интенсивности и их знаки зависят от населённостей и базиса.
Смысл квантовых параметров на этом этапе разбирать не требуется.

Таблицы ниже — стартовая гипотеза для порошкового спектра одного триплета S=1,
изотропного g и режима |D|,|E| значительно меньше частоты СВЧ. Нужен прямой
абсорбционный отклик: **a — положительная абсорбция, e — отрицательная эмиссия**.
Порядок букв — по возрастанию поля. Проверь фазу/знак и harmonic; лепестки
производной не считай отдельными a/e-переходами. Не меняй знак данных ради таблицы.

## 1. По a/e-паттерну выбери стартовый базис населённостей

Для РП-ИКК (RP-ISC) проверь `eigen`. Числа идут по возрастанию энергии:
`[p_-, p_0, p_+]`. При принятой ниже конвенции для D/E:

| Преимущественное смешивание | Стартовые населённости eigen | D > 0 | D < 0 |
|---|---|---|---|
| S–T0 | [0,1,0] | aeeaae | eaaeea |
| S–T+ | [0,0,1] | e00ee0: только e | 0ee00e: только e |
| S–T− | [1,0,0] | 0aa00a: только a | a00aa0: только a |

Здесь **0 — отсутствующий в идеальном пределе переход**, а не потерянный
экспериментальный пик. Для T+/T− не требуй шесть ненулевых особенностей:
в чистом пределе остаётся одна ветвь с тремя каноническими позициями.
В реальных срезах допускаются смеси населённостей и последующая релаксация.
Таблица T0 подтверждена источником [1]; строки T+/T− следуют из знаков
`p_-−p_0` и `p_0−p_+` и порядка канонических полей, а не из отдельного
экспериментального критерия механизма.

Для следующих паттернов проверь `xyz`. Готовые стартовые варианты:

| Старт [px,py,pz] | D > 0, E > 0 | D < 0, E < 0 |
|---|---|---|
| [0.8,0.1,0.1] | eaeaea | aeaeae |
| [0.1,0.8,0.1] | eeaeaa | aaeaee |
| [0.1,0.1,0.8] | aaaeee | eeeaaa |
| [0,0.5,0.5] | aeaeae | eaeaea |
| [0.5,0,0.5] | aaeaee | eeaeaa |
| [0.5,0.5,0] | eeeaaa | aaaeee |

Это таблица стартов в высокополевом приближении при E/D >= 0, не доказательство
механизма и не единственное решение. Если паттерн не установлен или несколько
вариантов подходят, сохрани неоднозначность и сравни минимальное число кандидатов
xyz/eigen с отдельными fit_id. Не выводи знак D только из геометрии пиков.
Для перекрывающихся компонент, позднего среза или сильного смешения уровней
не навязывай эти идеальные строки; итог проверяет полный симулятор.

## 2. По положениям особенностей оцени стартовые D и E

Для разметки ищи выраженные максимумы и минимумы; затем выдели особенности
абсорбционных/эмиссионных линий относительно фона. Тип экстремума сам по себе
не задаёт a/e. Точки смены кривизны отдельно пиками не считай.
В принятой конвенции D/E используй правила начального назначения:

- Шесть надёжных пиков по возрастанию поля: Z_left, Y_left, X_left,
  X_right, Y_right, Z_right — кандидаты на оба перехода одного триплета.
- При неполном наборе рассматривай каждую половину отдельно, между центром
  и уже выделенным Z-пиком; сам Z в число внутренних пиков не включай.
- **Два внутренних пика: ближайшему к центру назначь X, более удалённому — Y.**
  Сохрани оба положения для оценки E. Это назначение меток; варьирование
  числовых параметров определяется конфигурацией фита.
- Один внутренний пик: кандидат на объединённое положение X–Y;
  E пока не разрешён. Это не устанавливает E=0.

Сначала вызови готовый детектор на очищенном срезе из корня проекта:

```bash
../.mars_env/bin/python src/utils/signal_bounds.py \
  --input "$SLICE_CSV" --direction both --noise-points 10 \
  --factor 3 --min-run 3 --margin 3 --peak-candidates --report "$NEW_BOUNDS_JSON"
```

Каталог отчёта должен существовать, путь — новый. В контекст бери только JSON.
Все координаты поля в нём — **T**, даже если CSV записан в G.
Детектор находит пороговые края и отдельно крайние выраженные пики-кандидаты.
`found` означает успех поиска границ; `edge_peak_candidates.status=candidates`
ещё не подтверждает Z. Проверь, что это две внешние Z-особенности одного
триплета, без примеси/артефакта и с обеими ветвями. Пороговые края лежат на
крыльях линий: **не подставляй threshold_span или padded-границы вместо расстояния
между Z-пиками**. При partial/not_found/inconsistent или отсутствующем Z
оставь оценку неопределённой и используй диапазон поиска. Настройки меняй по
разрешению/шуму данных, сохраняя их; массивы не выводи. Детали — только при
необходимости в [SIGNAL_BOUNDS](../src/utils/SIGNAL_BOUNDS.md).

Затем найди максимумы и минимумы готовым скриптом:

```bash
../.mars_env/bin/python src/utils/find_peaks.py \
  --input "$SLICE_CSV" --range "$B_LEFT_T" "$B_RIGHT_T" \
  --report "$NEW_PEAKS_JSON"
```

`B_LEFT_T/B_RIGHT_T` — `boundaries.left/right.padded_coordinate` при найденных
границах; без надёжной пары убери `--range`. По умолчанию фильтры высоты и
prominence равны тройному максимуму шума первых 10 точек; ширина >= 3 отсчётов,
расстояние между пиками одного типа >= 3. Меняй пороги по шуму/дискретизации,
сохраняя настройки. Список содержит только числовые экстремумы: назначай
X/Y/Z и a/e самостоятельно по правилам выше, не требуй ровно шесть кандидатов.
При `output_complete=false` список в терминале усечён: используй полный отчёт
или уточни фильтры; `n_peaks` хранит полный счёт. Массивы в контекст не выводи.
Форматы/параметры при необходимости — [FIND_PEAKS](../src/utils/FIND_PEAKS.md).

Рабочая конвенция: **D != 0, 0 <= E/D < 1/3; при E != 0 знаки E и D совпадают**.
E=0 — допустимый аксиальный предел. При смене конвенции осей переноси также
порядок населённостей; E→−E соответствует перестановке x/y, включая px/py
и остальные величины, связанные с этими осями. Знак E отдельно не переворачивай.

Пусть шесть канонических позиций `B1 < B2 < ... < B6` выражены в T,
`k = g_start * (mu_B/h)` в Hz/T. До шага 3 можно взять g_start=2.0023.
Если оба Z-пика подтверждены, `B_Z_left=B1`, `B_Z_right=B6` и
`delta_B_Z=B_Z_right-B_Z_left`. Тогда **|D_start|=k*delta_B_Z/2**.
Это расстояние, а **центр — полусумма координат Z-пиков**, не расстояние.
В первом порядке:

```
w_z = B6-B1; w_y = B5-B2; w_x = B4-B3
|D_start| = k*w_z/2
|E_start| = k*(w_y-w_x)/6
контроль: w_z приблизительно равно w_y+w_x
```

D/E получаются в Hz; для МГц дели на 1e6. Присвой обоим один выбранный знак.
Числа — только начальная оценка: уширение и смешение уровней смещают экстремумы,
поэтому канонические позиции не всегда совпадают с шестью крупнейшими пиками.

Если установлена одна чистая ветвь T+/T− и видны все её три канонические позиции
`C1<C2<C3`: `B_center=(C1+C2+C3)/3`; `C_z` — наиболее удалённая от центра
позиция, `C_u,C_v` — две остальные. Тогда
`|D_start|=k*|C_z-B_center|`, `|E_start|=k*|C_u-C_v|/3`.
При неполном наборе, неразрешённых линиях или наложении другого сигнала не
выдумывай отсутствующие позиции: используй диапазон поиска и численное сравнение.

## 3. По центру оцени стартовый g_iso

При двух подтверждённых Z-пиках возьми
**`B_center=(B_Z_left+B_Z_right)/2`**. Для проверки можно сравнить со средним
трёх центров пар: `((B1+B6)+(B2+B5)+(B3+B4))/6`, если все шесть позиций установлены.
`edge_peak_candidates.midpoint` пригоден только после подтверждения этих пиков как Z;
`threshold_midpoint` — середина порогового диапазона, не установленный центр Z.
Для чистой трёхлинейной ветви —
среднее C1,C2,C3 по шагу 2. Не используй центр, взвешенный знаковой интенсивностью.

```
g_iso_start = h*nu/(mu_B*B_center)
            = nu_Hz/(1.39962449171e10 * B_center_T)
            = nu_GHz/(13.9962449171 * B_center_T)
```

Частоту бери из метаданных именно этого измерения; 1 G=1e-4 T,
1 mT=1e-3 T. Константа — CODATA 2022 [3]. Без частоты или надёжного центра
не выдавай вычисленный g за определённый по данным. С новым g один раз
уточни стартовые |D|/|E| из шага 2; окончательные значения даёт фит.

## Подбор, проверка, отчёт

До подбора сохрани кратко: источник, a/e-паттерн, базис и порядок населённостей,
знак-кандидат D/E, старты, границы, vary, новый fit_id и бюджет. Сумма трёх
населённостей — 1; третья свободная зависима. Не фиксируй стартовые чистые
населённости навсегда: их можно варьировать в [0,1]. Для 2D впоследствии
наследуются базис, гамильтониан и ham_strain; T1=eigen, потери=xyz.

Готовые фитеры и ключи найди в [index](../index.md); точную команду/формат при
необходимости дочитай в нужном разделе [README](../src/fit_utils/README.md).
Не читай всю документацию и предметную онтологию перед численным подбором.
Перед итоговой проверкой прочитай [fit-acceptance](fit-acceptance.md) и команды
шума/доводки в разделах «Проверка после фита» и «Обязательная контрольная доводка»
[spectra-modeling](spectra-modeling.md). Перед сдачей отрисуй наложение эксперимента
и итогового фита:

```bash
../.mars_env/bin/python src/utils/draw_fit_1d.py \
  --fit "$FIT_NPZ" --spectrum-id "$SPECTRUM_ID" --fit-id "$FIT_ID" \
  --output-dir "$FIT_OUTPUT_DIR"
```

Нужен `fitdraw_<spectrum_id>.svg` и успешный `check_fit_draw_1d.py` по полному
вызову в AGENTS.md; детали оформления — [fit-drawing](fit-drawing.md).
Все пять проверок (шум, Пирсон/контроль D/E, доводка, таблица, рисунок) обязательны.
Для `check_fit_perturbation_1d.py` требуются `r >= 0.32` и
`Q_original <= Q_control` при `D'=-2D, E'=-E`, остальные параметры и масштаб
фиксированы. Полная команда — AGENTS.md, §1.3; снимок тот же, что для доводки.

Детекторы границ и максимумов/минимумов доступны. Назначение X/Y/Z,
a/e-классификация и расчёт стартов по формулам выполняются агентом.
Согласование старых валидаторов со знаковыми D/E также ещё требуется:
нынешний табличный контроль требует положительный D. Отрицательный D не заменяй
модулем ради прохождения проверки и не объявляй такой результат принятым.

В техническом дневнике достаточно команд, файлов и метрик. Перед физической
интерпретацией или написанием содержательного отчёта догрузи только относящиеся
к выводам определения/правила по [ontology-context](ontology-context.md).

Источники для отчёта; при подборе заново не открывай:
[1 — T0 и знак D](https://pmc.ncbi.nlm.nih.gov/articles/PMC5875436/),
[2 — базисы и порядок населённостей](https://easyspin.org/documentation/spinpolarization.html),
[3 — mu_B/h](https://physics.nist.gov/cgi-bin/cuu/Value?mubshhz%7Ccategory=elecmag_in).
Формулы позиций и таблица xyz — первое приближение для используемой конвенции
`H/h=(mu_B/h)*g*B*Sz+D*(Sz^2-S(S+1)/3)+E*(Sx^2-Sy^2)`;
не загружай вывод формул на этапе подбора.
