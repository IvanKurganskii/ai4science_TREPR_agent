# Проверка таблицы и параметров фита

Версия: 2026-11-09.1. Корень проекта — каталог с [AGENTS.md](../AGENTS.md).
Модуль обязателен для подбора и проверки 1D/2D-фитов вместе с
[spectra-modeling](spectra-modeling.md). В СПРАВКА только объясняй правила;
расчёты, проверки результата и запись файлов относятся к ЗАДАЧА.

Переход на знаковую конвенцию из [fit-slice](fit-slice.md): целевое условие
`100 <= abs(D_MHz) <= 10000`, `0 <= E_MHz/D_MHz < 1/3`, D != 0.
При E != 0 знаки D/E совпадают. Таблица ниже фиксирует **текущее поведение**
старого скрипта: он пока требует положительный D и не проверяет совпадение
знаков. Согласование валидаторов — следующий этап автоматизации. До него
успех скрипта не доказывает новую конвенцию; проверяй её отдельно по параметрам,
а D<0 оставляй промежуточным результатом с явным указанием несовместимости.
Не подменяй D модулем, не меняй данные и не объявляй непройденную проверку успешной.

## Дополнительные критерии готовности

Успешные проверки шума и контрольной доводки остаются обязательными.
Дополнительно каждый итоговый фит должен пройти `check_fit_table.py`:
код 0, статус `passed`, новый сохранённый JSON-отчёт. Также обязателен SVG по
[fit-drawing](fit-drawing.md): 1D — наложение фита и эксперимента; 2D — шесть
кинетик и шесть срезов в одном рисунке. Нужен успешный `check_fit_draw_1d.py`
либо `check_fit_draw_2d.py`; полные команды — в AGENTS.md, §1.3.
Дополнительно обязателен `check_fit_perturbation_1d.py` либо
`check_fit_perturbation_2d.py`: сначала `r_Pearson >= 0.32`, затем
`Q_original <= Q_control` для `D'=-2D, E'=-E`. Все остальные параметры и
масштаб фиксированы, включая исходный делитель нормирования. При смене знака
не переставляй населённости. Контроль не подбирается и может выходить за
границы исходного поиска; не обрезай его и не пропускай. Код 0/`passed` и
новый JSON обязательны. Команды — AGENTS.md, §1.3; договор —
[PERTURBATION_CHECKS](../src/utils/PERTURBATION_CHECKS.md).
Включай все пять проверок
в «Готово, когда» до подбора. После изменения параметров, текущей строки или
условий расчёта повтори проверки для итоговой версии.

| Условие | 1D-срез | 2D-спектр |
|---|---|---|
| Таблица | `results/tables/1d-fit_results.csv` | `results/tables/2d-fit_results.csv` |
| Текущая запись | Ровно одна строка с заданными `spectrum_id` и `fit_id` | То же |
| D | `100 <= D_MHz <= 10000` | То же |
| E | Конечное число, `E_MHz / D_MHz < 1/3` строго | То же |
| g | От 1 до 4 включительно; для нескольких g — каждый | То же |
| px, py, pz | Каждый в [0,1]; `abs(px+py+pz-1) <= 1e-6` | То же |
| lw_Gs | `0 < lw_Gs < 20`, границы исключены | То же |
| t_x, t_y, t_z, T_1 | Не требуются | Все четыре в [0.1,100000] мкс включительно |

Все перечисленные параметры должны присутствовать и быть конечными числами.
Пустые значения, None/null, NaN, +Inf/-Inf недопустимы; None не означает
«параметр фиксирован». Остальные необходимые параметры модели также сохраняй
полностью в снимке для независимого воспроизведения. Условия физической модели
и её ограничения сохраняются: этот контроль их не отменяет. Отношение E/D
проверяется именно как записано в критерии, без замены на абсолютное значение.

## Формат таблиц

CSV UTF-8, разделитель — запятая, первая строка — названия столбцов;
перед ней допустимы комментарии `#`. Обязательные столбцы для 1D:

```csv
spectrum_id,fit_id,D_MHz,E_MHz,g,px,py,pz,lw_Gs
slice_001,fit_001,1000,100,2.0023,0.2,0.5,0.3,3
```

Для 2D нужны ещё четыре столбца; их единицы — **мкс**:

```csv
spectrum_id,fit_id,D_MHz,E_MHz,g,px,py,pz,lw_Gs,t_x,t_y,t_z,T_1
map_001,fit_002,1000,100,2.0023,0.2,0.5,0.3,3,5,1,10,50
```

Числа примеров показывают формат, не являются результатами текущего проекта.
Дополнительные столбцы для путей, модели и пояснений допустимы. Для тензорного
g или двух g-факторов ячейка `g` содержит JSON-массив из 2/3 чисел, корректно
заключённый в кавычки CSV, например `"[2.0,2.01,2.02]"`.

`spectrum_id` однозначно обозначает текущий срез или 2D-измерение, `fit_id` —
конкретную сохранённую версию фита. Передавай те же идентификаторы в проверку.
Строка другого среза/версии и дубликаты этой пары не подходят. Существующие
записи сохраняй; новая версия получает новый `fit_id`. Заполняй строку из
реальных итоговых параметров, сверяй её со снимком и артефактами фита.
Таблицы отдельных вертикальных CSV TPE/COBYLA (`parameter,value,unit`)
недостаточно: из них нужно составить строку сводной таблицы с идентификаторами.
Если сводной таблицы ещё нет, создай её в рамках разрешённой задачи подбора.

Перед записью приведи единицы: D/E из Hz делятся на `1e6` для столбцов `_MHz`;
времена из секунд умножаются на `1e6` для мкс; ширина из T умножается на `1e4`
для G, **если это одна и та же определённая в модели ширина**. Зафиксируй,
что означает `lw_Gs` (например, Gaussian FWHM); не выдавай один `gauss` за
полную ширину при другом определении или наличии других вкладов в уширение.
Числовой контроль проверяет границы `lw_Gs`, а не выводит ширину из спектра.

Для нового фита записывай выбранный базис в дополнительный столбец
`population_basis`: xyz/product/eigen/zfs/multiplet/zeeman. В столбцах px/py/pz
хранятся три упорядоченных числа именно этого базиса: в xyz — T_x/T_y/T_z,
в product при S=1 — m_S=+1,0,-1, в eigen/zfs — по возрастанию энергии.
Это сохраняемые имена столбцов, не переименование физических состояний.
Старые строки без столбца считаются xyz. Не меняй базис чисел без преобразования
матрицы плотности, если нужно сохранить исходное физическое состояние.
В актуальном 2D-фитере времена `tau_out_x/y/z` — потери из XYZ-подуровней;
записывай их в t_x/y/z в мкс. `T_1` — параметр `tau_intra` для соседних переходов
между собственными уровнями гамильтониана (eigen), базовая скорость 1e6/T_1 s⁻¹
с тепловыми правилами MaRS. Для иной кинетической модели явно определи связь.
Не подставляй произвольные числа ради прохождения границ.

По умолчанию D ищется в 500–3000 МГц, пределы приёмки остаются 100–10000 МГц.
Агент может выбрать границы и маску через [общий контракт](../src/fit_utils/README.md),
не правя код. Сохрани их до нового запуска и используй в независимом контроле;
не меняй сам критерий и не обрезай готовые параметры ради приёмки.

## Запуск

Из корня проекта в WSL используй существующую среду и защищённую оболочку.
Заранее задай идентификаторы и новый путь отчёта; его родительский каталог
должен существовать внутри проекта.

```bash
../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_table.py" \
  --root "$PWD" --dimension 1d --spectrum-id "$SPECTRUM_ID" --fit-id "$FIT_ID" \
  --report "$NEW_PARAMETERS_REPORT_JSON"
```

Для 2D замени `--dimension 1d` на `--dimension 2d`. Таблица выбирается по типу
автоматически. Скрипт не запускает MaRS, не исправляет и не нормирует параметры,
не меняет таблицу, спектры или старые отчёты. Он проверяет указанную строку,
а не все записи истории; JSON содержит идентификаторы, строку, SHA-256 таблицы,
проверенные значения и ошибки.

Код 1/`failed` — критерий нарушен либо нужная строка отсутствует/неоднозначна.
Код 2/`invalid` — нет таблицы/столбцов, неверен формат или нельзя сохранить новый
отчёт. Только код 0/`passed` подтверждает эту проверку. Сохрани в задаче команду,
идентификаторы, отчёт и фактический статус. Шумовой и контрольный отчёты сохраняй
отдельно, как и отчёты контроля D/E и рисунка; ни один из пяти не заменяет остальные. Если готовый инструмент не
поддерживает эти условия, подбери совместимый инструмент или зафиксируй блокировку.
