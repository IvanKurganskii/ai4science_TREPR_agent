Для каждого сдаваемого фита **все пять** проверок требуют код 0, `passed`,
отдельные новые JSON-отчёты; команды, входы, метрики и отчёты запиши в задаче.
До подбора прочитай [fit-acceptance](fit-acceptance.md): таблицы, идентификаторы,
границы параметров, единицы и команда проверки. Включи условия в «Готово, когда»;
пороги обоснуй до поиска, не выдавай их за ранее согласованные. После изменения
итога повтори все пять проверок. Иной статус, ошибка, тайм-аут, пропуск или
отсутствие отчёта означают незавершённый фит; сохраняй промежуточный результат.
Малый loss и завершение оптимизатора не заменяют приёмку.

## Порядок моделирования

Для старта 1D используй три шага из fit-slice: a/e → базис/населённости;
положения → D/E с 0 <= E/D < 1/3; геометрический центр → g_iso. Это рабочие
оценки, не физическая интерпретация. Перечень ниже описывает общий конвейер.

1. Скриптом получи список файлов, метаданные и краткую сводку processed/slices;
   массивы в контекст не выводи. Готовые интерфейсы: mars_simulation для расчёта,
   fit_utils для подбора. Исходники/документацию читай только при необходимости.
2. Начни с 1D по fit-slice. Сравнивай результаты численными метриками, сохраняй
   параметры и спектры в results/fits/1d; продолжай до критериев качества.
3. Повтори для второго среза, если он есть. Общий гамильтониан фиксирован;
   менять его можно только при совместном подборе соответствующих срезов.
   При невозможности согласия укажи ограничение описания данных.
4. После определения гамильтониана переходи к 2D-населённостям и кинетике.
5. Агент может пересмотреть границы/маску для нового fit_id и бюджета;
   критерии приёмки не меняются. Недостающий код опирай на готовые инструменты
   и library/mars_documentation; доступны MaRS/nevergrad/optuna.

## Как использовать `src/mars_simulation`

Запускай из корня проекта в WSL через существующую среду и защищённую оболочку.
Это локальный CLI для расчёта при заданных параметрах; подбор он не выполняет.

```bash
../.mars_env/bin/python -m src.mars_simulation --help
../.mars_env/bin/python -m src.mars_simulation --request "$SIM_REQUEST_JSON" \
  --output-dir "results/mars_simulations/$RUN_ID"
```

`SIM_REQUEST_JSON` — JSON-запрос задачи, `RUN_ID` — новый идентификатор запуска.
Форма: `{"name":"имя_операции","arguments":{...}}`; `id` необязателен.
Проверяй код завершения, `result.ok/error`, сводку и предупреждения.
Пути — в `result.artifacts`, снимок гамильтониана и настроек — в `result.spin_model`.

| Имя операции | Обязательные данные |
|---|---|
| `simulate_high_j_1d`, `simulate_moderate_j_1d` | `hamiltonian`, `populations`, `field_axis`; дополнительные настройки — `settings` |
| `simulate_high_j_2d`, `simulate_moderate_j_2d` | Сохранённый `spin_model`, `context`, `field_axis`, `time_axis`; гамильтониан фиксирован |
| `simulate_high_j_2d_full`, `simulate_moderate_j_2d_full` | Явные `hamiltonian`, `context`, обе оси; дополнительные настройки — `settings` |

`high_j` — эффективный триплет S=1: `g`, `D`, `E`, `gauss`, `lorentz`.
`moderate_j` — пара S=1/2: `g0`, `delta_g`, `D`, `E`, `J`, `gauss`, `lorentz`;
g-факторы равны `g0 ± delta_g/2`, обмен задан как `+J*S1·S2`. D/E/J и частота
заданы в Hz, ширины FWHM — в T, температура — в K. Требуется `|E| <= |D|/3`
и хотя бы одна положительная ширина. Оси: `{"start":...,"stop":...,"points":...}`
либо `{"values":[...]}`; поле в T, время в s от приготовления состояния,
координаты неотрицательные и строго возрастают. Начало модели не определяет
автоматически время лазера на экспериментальной оси.

Пример 1D; значения демонстрационные. Перед расчётом подставь условия задачи,
для сравнения используй фактическую сетку измерения.

```json
{
  "name": "simulate_high_j_1d",
  "arguments": {
    "hamiltonian": {"g": 2.02, "D": 180000000, "E": 10000000,
                    "gauss": 0.001, "lorentz": 0.0},
    "populations": {"p_x": 0.2, "p_y": 0.7, "p_z": 0.1},
    "field_axis": {"start": 0.325, "stop": 0.37, "points": 101},
    "settings": {"freq": 9800000000, "temperature": 80, "mesh": 25,
                 "device": "cpu", "dtype": "float64", "harmonic": 0},
    "population_mode": "raw", "normalization": "none",
    "output": {"name": "triplet_1d", "include_data": false, "save_plot": false}
  }
}
```

Для 2D перенеси **полный фактический** `result.spin_model` из 1D в аргумент
`spin_model`, добавь `time_axis` и `context`; вместо `populations` населённости
задаются внутри `context`. Для high-J нужны `p_x/p_y/p_z`, `tau_intra`,
`tau_out_x/tau_out_y/tau_out_z`; для moderate-J — также `p_s`, вместо
`tau_intra` — `tau_outer/tau_inner`, дополнительно `tau_out_s`.
Все времена жизни заданы в микросекундах, все ключи context обязательны;
`null` отключает соответствующую скорость. `rise_time_us` необязателен и
меняет сигнал на `S(B,t) - S(B,0)*exp(-t/T)`; сохраняй его в условиях расчёта.
Вариант `2d_full` не разрешает менять уже зафиксированный гамильтониан в обход
порядка моделирования выше.

Населённости здесь — относительные веса [0,1] выбранного `population_basis`, а не
обязательно вероятности с суммой 1; для пары есть ещё синглет. Явно выбирай
`population_mode`: `raw` сохраняет веса, `minmax`/`max` их преобразуют.
Умолчание `notebook` различается: high-J 1D — minmax, high-J 2D — raw,
moderate-J — max. Не меняй его незаметно при переносе 1D → 2D. `normalization`
равно `none` либо `maxabs` по всему массиву; знаки абсорбции/эмиссии сохраняются.
`harmonic: 0` — абсорбция/эмиссия, `1` — первая производная. Начинай с
`mesh: 25` по умолчанию; слишком грубая сетка может дать нулевой спектр.

Артефакты: числовой NPZ с `fields_T`, `spectrum`, `raw_spectrum`,
`metadata_json`; у 2D также `times_s` и порядок `(time, field)`. JSON хранит
снимок и условия; PNG необязателен. Проверяй массив скриптом на ненулевость,
NaN/Inf, а не только `ok`. Для проверки фита ключ `spectrum` выбирай явно через
`--fit-key spectrum`. Не выводи массив в контекст, оставляй `include_data: false`.

Поля — [schemas.py](../src/mars_simulation/schemas.py), запросы и Python API —
[examples/](../src/mars_simulation/examples/). Замени пути и числа примеров.
Полный `tool_schemas.json` в контекст не загружай. Python API:
`MarsSimulationTools(...).dispatch(name, arguments)` возвращает `ok` без
CLI-обёртки. `--serve` принимает JSON-запрос/ответ на строку; это не MCP.

## Подбор среза: общая настройка всех фитеров

При настройке интерфейса дочитай нужный раздел [контракта параметров](../src/fit_utils/README.md).
Он обязателен для `tpe_search.py`, `cobyla_fit.py` и `src/agent_utils/fit_1d_slice.py`.
Общие настройки: `--fit-config JSON`, `--bounds PARAM LOW HIGH`,
`--initial PARAM VALUE`, `--fix PARAM VALUE`, `--vary PARAM`.
`--print-fit-config` показывает разрешённую конфигурацию без чтения данных/фита.

Агент самостоятельно выбирает границы, стартовые значения и свободные/фиксированные
параметры для новой версии фита. Перед запуском сохрани конфигурацию, обоснование,
новый `fit_id`, число независимых координат и бюджеты; при пересмотре после
попытки создай новую версию, не исправляй задним числом историю. Ограничения
пользователя, совместность гамильтониана нескольких срезов и критерии приёмки
сохраняются. Согласовывать каждое рутинное изменение границ с пользователем не нужно.

По умолчанию D = **500–3000 МГц** (`5e8–3e9` Hz), старт 1500 МГц.
Остальные числовые параметры также имеют настраиваемые границы и флаг vary;
в том числе можно включить/зафиксировать strain и Lorentz, выбрать базис,
задать границы частоты/температуры при необходимости. Выключение параметра —
фиксация значения, а не удаление из модели. Численные настройки harmonic/mesh
выбираются отдельно и не оптимизируются ради уменьшения loss.

Частотные параметры — Hz, ширины — T. Населённости лежат в своих границах,
фиксированные не перенормируются; последняя свободная определяется из суммы 1.
Непрерывный COBYLA использует именованные координаты; при нескольких разрешённых
базисах выполняется перебор с разделением общего бюджета. При всех фиксированных
параметрах модель оценивается без оптимизатора.

Отдельные TPE и COBYLA используют один симулятор MaRS и maxabs-MSE; третий CLI
выполняет TPE → Cobyla через MaRS SpectrumFitter. Dashboard отключён. Все входы:
двухстрочный CSV (поле по умолчанию G), числовой NPY `(N,2)` или NPZ
`field/intensity` (поле по умолчанию T). Для иных единиц укажи `--field-unit`;
канонический NPZ другого модуля сначала явно преобразуй к формату среза.

Всегда задавай новый `--output-dir`. Контракт сохраняется в `*_fit_config.json`,
полные лучшие параметры — в CSV/JSON, числовая симуляция — NPZ.
COBYLA наследует границы, маску, значения и настройки из CSV TPE вместе с его
ссылочным JSON; явные новые опции их переопределяют. Автоматического сужения границ
между стадиями нет. В NPZ `intensity` — расчёт в масштабе экспериментального
max(abs), `simulated` — сырой; для шумового контроля нужен `--fit-key intensity`.
`n_free_model` не включает дополнительную калибровку амплитуды проверки.

Конфигурация поиска не меняет допуски из fit-acceptance. Текущий независимый
адаптер поддерживает ham_strain и фиксированный population_basis; вариация
частоты/температуры и категориальный поиск базиса в контрольной COBYLA не поддерживаются.
Проверь совместимость до подбора; не удаляй физический параметр ради проверки.
CSV/контракт поиска не заменяет полный снимок по REFIT_CHECKS. Нужна точная
воспроизводимость сдаваемой модели; невозможность контроля фиксируй как
незавершённый результат. Собственная доводка не заменяет независимую проверку.

## Подбор 2D-контекста

Перед подбором high-J прочитай [README_2D](../src/fit_utils/README_2D.md).
`tpe_search_2d.py`, `cobyla_fit_2d.py`, `fit_2d_context.py` подбирают населённости,
времена потерь/релаксации и `rise_time_us`; гамильтониан, ширины и условия из
среза фиксированы. Агент выбирает их границы/vary через отдельный 2D-контракт.
Нужны полный 1D-снимок/CSV, новый fit_id и явный `--time-zero-ns`;
0–500 нс — окно шума, не определение времени лазера. Рост уже реализован как
`S(B,t)-S(B,0)*exp(-t/rise_time)`. COBYLA — через MaRS, без Dashboard.
Наследуй контракт/лучшую точку через `--previous-fit REPORT`, не меняй гамильтониан.
Базис населённостей наследуется из 1D; агент может выбрать другой через `--basis`
или `population_basis` в JSON для нового fit_id. T1 (`tau_intra`) всегда в eigen,
потери (`tau_out_x/y/z`) всегда в xyz. Ненулевой ham_strain переносится из 1D
и фиксирован; в этих 2D-модулях его варьирование запрещено. Сохраняй все три
базиса и strain в снимке/отчёте. Порядок слотов населённостей определяется базисом.
Для проверок используй созданный снимок, `--fit-key spectrum`, одинаковые смещение
времени, эффективное окно и n_free_model из отчёта, `--alignment none`.
Перед сдачей выполни [fit-drawing](fit-drawing.md): один SVG с 6 кинетиками
и 6 временными срезами, выбранными агентом, эксперимент/модель в каждой панели.
Файл — `fitdraw_<spectrum_id>.svg`; обязателен успешный check_fit_draw_2d.py.
Статус `optimized_unchecked` не заменяет проверки шума/доводки, таблицы и рисунка.

## Проверка после фита

После каждого завершённого запуска подбора с сохранённым спектром вызови
[check_fit_1d.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_1d.py) для 1D или
[check_fit_2d.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_2d.py) для 2D. Это предметная проверка режима
ЗАДАЧА; в СПРАВКА её не запускай. Контракт форматов и опций описан в
[FIT_CHECKS.md](../src/utils/FIT_CHECKS.md).

До подбора зафиксируй в задаче окно шума, число независимых параметров, способ
нормирования и обоснованный верхний допуск `--max-k` для отношения остаточной
дисперсии к шумовой. Точное равенство K единице не требуется. Для текущих четырёх
измерений пользователь подтвердил, что вспышка позже 500 нс: используй
`--noise-window-ns 0 500`. Точное время вспышки неизвестно; не принимай 500 нс за
время нуля. Для новых измерений сначала установи безопасный предлазерный интервал.

Сохрани симуляцию вместе с её осями как числовой NPZ/CSV. Подставь фактические
пути и заранее установленные значения N_FREE/K_MAX в команду из корня проекта.
`NEW_NOISE_REPORT_JSON` — новый путь отчёта шумовой проверки для этого фита;
родительский каталог должен существовать. Для другого фита/запуска задай новый путь.

```bash
../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_1d.py" --root "$PWD" \
  --slice "$SLICE_CSV" --fit "$FIT_NPZ" \
  --noise-window-ns 0 500 --n-parameters "$N_FREE" --max-k "$K_MAX" \
  --report "$NEW_NOISE_REPORT_JSON"

../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_2d.py" --root "$PWD" \
  --data "$DATA_2D" --fit "$FIT_NPZ" \
  --noise-window-ns 0 500 --n-parameters "$N_FREE" --max-k "$K_MAX" \
  --report "$NEW_NOISE_REPORT_JSON"
```

Для 1D шум берётся из родительского обработанного 2D-измерения, указанного в
шапке среза; срез проверяется по родителю и своему временному окну. При неполных
метаданных укажи истинный `--source-2d`; не выбирай сырой файл по похожему имени.
Для усреднения/интегрирования укажи действительную операцию среза. Старые пути
`Source` сейчас не соответствуют именам сырых файлов; существующие срезы не меняй
ради проверки. Для 2D передай измерение с сохранённой предлазерной областью.

Код 0/`passed` означает соответствие заданному допуску, код 1/`failed` — его
превышение. Код 2 с `diagnostic` означает отсутствие допуска, с `invalid` — ошибку
или недостаток данных; ни один из этих статусов не означает прохождения проверки.
Запиши в задаче фактический статус, K, параметры вызова и входные файлы.
Корреляции после фильтрации и нелинейность фита ограничивают статистический смысл
K: проверка не выдаёт формального p-value и не заменяет анализ физических параметров.
Не меняй критерий после начала подбора ради приёмки; при блокировке/исчерпании
бюджета сохраняй промежуточный результат по AGENTS.md.

## Пирсон и контрольная модель D/E

Для каждого итогового 1D/2D-фита обязателен `check_fit_perturbation_1d.py`
либо `check_fit_perturbation_2d.py`. Полные команды — AGENTS.md, §1.3;
договор — [PERTURBATION_CHECKS](../src/utils/PERTURBATION_CHECKS.md).
Используй снимок, оси, окно сравнения, шум и N_FREE того же кандидата.
Проверка сначала требует знаковый `r_Pearson >= 0.32`; при неуспехе
контроль не рассчитывается, кандидат отвергается. Затем MaRS воспроизводит
сохранённый спектр и рассчитывает один контроль `D'=-2D, E'=-E`.
Требуется `Q_original <= Q_control`, с техническим допуском округления.
Все остальные параметры, базис и числовой порядок населённостей, масштаб,
смещение и делитель нормирования исходной модели сохраняются. В 2D сохраняются
также времена, рост сигнала и полная сетка симуляции; окно применяется после
расчёта. Контроль не оптимизируется, не обрезается по поисковым границам и
не заменяет исходный фит. При E=0 контроль также обязателен.
Сохрани новый JSON, код, `r`, `Q_original`, `Q_control` в задаче.
Только код 0/`passed` означает прохождение. Порог 0.32 не меняй ради приёмки;
ошибка, тайм-аут или пропуск контроля не являются успехом.

## Обязательная контрольная доводка (1D и 2D)

В режиме ЗАДАЧА перед объявлением подбора завершённым и сдачей параметров и
спектра обязательно выполни
[check_refit_1d.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/check_refit_1d.py) для среза или
[check_refit_2d.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/check_refit_2d.py) для 2D. Эти проверки включают
проверку относительно шума и дополнительно запускают MaRS Cobyla из параметров
ответа. Интерфейс — `SpectrumFitter`/`Spectrum2DFitter`, `backend="ng"`,
`optimizer="Cobyla"`; отдельный scipy-фит для этой проверки не используй.
Проверяй каждый итоговый фит соответствующим скриптом; если сдаёшь и срезы,
и 2D, нужны проверки обоих видов. Правка кода или инструкций, объяснение и
симуляция без подбора сами по себе не требуют запуска доводки.

До основного подбора зафиксируй модель, свободные параметры, исходные границы,
связи, окно сравнения, способ нормирования, `--max-k` и абсолютный/относительный
допуск улучшения. Вместе с итогом сохрани полный
JSON-снимок параметров и условий симуляции по [REFIT_CHECKS.md](../src/utils/REFIT_CHECKS.md).
Проверка сначала воспроизводит спектр из этого снимка. Нельзя менять нормирование,
сетку, набор свободных параметров или границы относительно исходной задачи.
Используй ту же цель K либо эквивалентную MSE; иной критерий требует отдельного
согласованного контроля. Для 2D сохраняй полную временную сетку симуляции:
`--fit-window-ns` ограничивает только сравнение, а не расчёт и нормирование модели.

Проверочный бюджет по умолчанию — 500 вызовов цели и 300 секунд на весь процесс.
Заранее учти его в бюджете эпизода. Иные `--budget` / `--time-limit-seconds`
зафиксируй до проверки; не уменьшай их после неудачи ради прохождения.
Передай заранее выбранные `--improvement-atol` и `--improvement-rtol`:
приёмка требует `initial_K - best_K <= atol + rtol * initial_K` и прохождения
критерия относительно шума. Точного равенства метрик не требуется.

Из корня проекта запускай подходящую команду в среде `../.mars_env`. Подставь
фактические пути и заранее выбранные числовые значения. `PARAMETERS_JSON` —
снимок именно сдаваемого фита; `NEW_REPORT_JSON` — новый путь для отчёта этого
запуска внутри проекта. Существующий отчёт не перезаписывай.

```bash
../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_refit_1d.py" --root "$PWD" \
  --slice "$SLICE_CSV" --fit "$FIT_NPZ" --parameters "$PARAMETERS_JSON" \
  --noise-window-ns 0 500 --n-parameters "$N_FREE" --max-k "$K_MAX" \
  --budget 500 --time-limit-seconds 300 \
  --improvement-atol "$DELTA_K_ABS" --improvement-rtol "$DELTA_K_REL" \
  --report "$NEW_REPORT_JSON"

../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_refit_2d.py" --root "$PWD" \
  --data "$DATA_2D" --fit "$FIT_NPZ" --parameters "$PARAMETERS_JSON" \
  --noise-window-ns 0 500 --n-parameters "$N_FREE" --max-k "$K_MAX" \
  --budget 500 --time-limit-seconds 300 \
  --improvement-atol "$DELTA_K_ABS" --improvement-rtol "$DELTA_K_REL" \
  --report "$NEW_REPORT_JSON"
```

Окно 0–500 нс относится к текущим четырём измерениям; для новых установи его
по правилам проверки шума выше. Сохрани те же параметры источника среза,
операции, единиц, выравнивания и окна сравнения, что использовались при оценке
фита. Для 2D при другом начале оси симуляции укажи фактический
`--fit-time-offset-ns`; это смещение не является автоматически временем лазера.

Только код 0 и статус `passed` подтверждают прохождение. При `failed` продолжи
основной подбор в оставшемся бюджете и проверь новый итог заново. `diagnostic`,
`inconclusive`, `invalid`, пропуск и отсутствие отчёта не позволяют объявить фит
проверенным. При невозможности завершить контроль сохрани промежуточный результат
и причину по workflow; ошибку окружения не исправляй самовольной установкой пакетов.

Общие свободные параметры нескольких срезов требуют совместного контроля;
скрипт одного среза такую приёмку не подтверждает. При фиксированном гамильтониане
контроль среза варьирует только разрешённые параметры этого среза.
Сохрани отчёт через `--report`; в задаче запиши команду, входные файлы, путь отчёта,
код возврата, фактический статус, `initial_k`, `best_k` и улучшение, затем допиши
дневник по workflow. Улучшенный проверочный фит служит поводом продолжить основной
подбор; исходный ответ и существующие данные он автоматически не заменяет.
В СПРАВКА расчёты не запускай.
