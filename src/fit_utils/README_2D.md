# 2D-фиты контекста с гамильтонианом из среза

Этап для эффективного триплета **high-J, S=1**. Гамильтониан, Gaussian/Lorentz
FWHM, `ham_strain`, частота, температура, гармоника, ориентация и сетка берутся из сохранённого
1D-фита и остаются фиксированными. Изменить их через контракт 2D-подбора нельзя.
Модель пары moderate-J этими фитерами пока не поддерживается.

| Модуль | Запуск из корня проекта |
|---|---|
| `tpe_search_2d.py` | Глобальный Optuna TPE |
| `cobyla_fit_2d.py` | Локальный MaRS `Spectrum2DFitter`, Nevergrad `Cobyla` |
| `fit_2d_context.py` | TPE → MaRS Cobyla; также `--method tpe/cobyla/two-stage` |
| `context_parameters.py` | Контракт, границы, маска варьирования, вероятности с суммой 1 |

Dashboard не запускается. Python API без записи файлов:
`ContextFitProblem(...)`, `run_tpe(problem, ...)`, `run_cobyla(problem, ...)`,
`run_two_stage(problem, ...)`. Вычисление использует существующий
`src.mars_simulation.engine.SimulationEngine`, не отдельную реализацию физики.

## Перенос 1D → 2D

`--from-1d PATH` (синоним `--spin-model`) принимает:

- полный JSON `spin_model` с `model/hamiltonian/settings`;
- JSON метаданных/ответа `mars_simulation` с полем `spin_model`;
- полный вертикальный `parameter,value,unit` CSV трёх текущих 1D-фитеров.
  Переноси его вместе со ссылочным `*_fit_config.json`;
- JSON параметров, если он содержит все параметры, частоту, температуру,
  гармонику и сетку; при отсутствии последних используй полный CSV.

D/E и частота — Hz, gauss/lorentz — T, `ham_strain` — Hz, температура — K.
У CSV сохраняются фактические `g_iso`, D/E, gauss/lorentz, ham_strain,
freq/temperature, harmonic/mesh и **базис населённостей**. Ненулевой ham_strain
разрешён и остаётся фиксированным: его нельзя включить в vary в этих 2D-фитерах.
Полный `spin_model` поддерживает также анизотропный g и три компоненты ham_strain.

Населённости среза служат **стартом**, а не утверждением о населённостях сразу
после лазера. В 2D они находятся внутри контекста и по умолчанию подбираются.
Исходный файл и гамильтониан не перезаписываются; отчёт хранит пути и SHA256.

Базис из CSV `basis` либо JSON-метаданных `population_basis` наследуется вместе
с населённостями. Для отдельного JSON гамильтониана без информации о населённостях
используется прежнее умолчание xyz; можно добавить `population_basis` рядом с
`model/hamiltonian/settings` либо явно выбрать базис через CLI.

Агент выбирает базис начальных населённостей для каждого запуска:
`--basis xyz/product/eigen/zfs/multiplet/zeeman` (синоним `--population-basis`)
либо корневое поле JSON `population_basis`. В 2D выбранный базис фиксирован на
время одного фита; сравнение базисов оформляй разными fit_id. TPE и COBYLA
подбирают числовые параметры внутри этого базиса. Смена базиса сама по себе
не преобразует прежнее физическое состояние: для его сохранения нужно
преобразование матрицы плотности. При подборе новых населённостей это новая
постановка, которую нужно явно записать.

## Что можно варьировать

| Параметр | Старт | Границы по умолчанию | Смысл |
|---|---:|---:|---|
| `p_x`, `p_y`, `p_z` | 0.2, 0.5, 0.3, либо из 1D | [0,1] | Три начальные населённости в выбранном базисе |
| `tau_out_x/y/z` | 10 мкс | [0.1,100000] мкс | Потери триплетных подуровней |
| `tau_intra` | 10 мкс | [0.1,100000] мкс | Параметр внутритриплетной спиновой релаксации |
| `rise_time_us` | 0.2 мкс | [0.01,1000] мкс | Время начального роста |

По умолчанию все перечисленные параметры включены в подбор. У трёх населённостей
две независимые координаты, всего **7**. При N включённых населённостях независимы
N−1: последняя вычисляется из суммы 1. Фиксированные вероятности не меняются;
границы всех трёх, включая зависимую, соблюдаются. Несовместимые границы вызывают
ошибку до симуляции. Старт свободного параметра вне новых границ переносится к
ближайшей границе; только свободные населённости приводятся к допустимой сумме.

Алиасы: `pop_x/y/z` и `px/py/pz` → `p_x/y/z`, `t_x/y/z` → `tau_out_x/y/z`,
`T1` и `T_1` → `tau_intra`. Названия трёх слотов p_x/y/z сохранены для
совместимости: в xyz это T_x/T_y/T_z, в product для S=1 — m_S=+1,0,-1,
в eigen/zfs — уровни в порядке возрастания энергии. Всегда сохраняй базис
рядом с числами; не подписывай населённости product как физические XYZ.
Все времена в JSON и `--bounds/--initial/--fix` заданы **в микросекундах**.
Времена используют `scale: "log"` по умолчанию, вероятности — `"linear"`.
Шкала времени может быть заменена на `"linear"`; физические границы те же.

Контекст разделён на три части. Начальные населённости используют выбранный
`population_basis`; потери `tau_out_x/y/z` всегда заданы в **xyz**;
`tau_intra`/T1 — всегда в **eigen**, для соседних уровней по энергии.
T1 задаёт базовую скорость `1e6/tau_intra` в s⁻¹ с тепловыми правилами MaRS;
это параметр используемой кинетической модели, не универсальный вывод времени
затухания любой наблюдаемой величины. Его значение записывай в `T_1` таблицы
в мкс с этим определением. Базис населённостей не меняет базисы потерь и T1.

## Начальный рост

Он уже реализован в `SimulationEngine`:

`S_growth(B,t) = S_MaRS(B,t) − S_MaRS(B,0) · exp(−t/rise_time)`.

Сигнал при t=0 равен нулю. Для одного затухающего компонента получается
`S0(B) · [exp(−t/tau_decay) − exp(−t/rise_time)]`. Для нескольких мод распада
поправка вычитается из всей MaRS-кинетики. Это заданная форма начального роста,
не свёртка с приборной функцией и не две экспоненты с независимыми амплитудами.
Если нуля нет в измеренной сетке, движок вычисляет S(B,0) дополнительно.

`--fix rise_time_us null` отключает рост; положительное фиксированное число
сохраняет поправку, но запрещает подбор её времени. `null` допустим только для
фиксированных времён; для остальных времён он отключает соответствующую скорость.
Такой диагностический расчёт не отменяет требования приёмки о конечных временах.

## JSON и команды

Агент сам выбирает старт, границы и свободные параметры **для нового fit_id**.
`--fit-config JSON`, повторяемые `--bounds PARAM LOW HIGH`, `--initial PARAM VALUE`,
`--fix PARAM VALUE`, `--vary PARAM`, `--print-fit-config` работают аналогично 1D.
Контракт 2D содержит `schema_version`, `parameters` и необязательный
`population_basis`; settings и параметры гамильтониана в нём запрещены.
Пример частичного контракта:

```json
{
  "schema_version": 1,
  "population_basis": "product",
  "parameters": {
    "tau_out_x": {"value": 5, "bounds": [0.5, 500], "vary": true, "scale": "log"},
    "tau_out_y": {"value": 10, "bounds": [0.5, 500], "vary": true},
    "tau_out_z": {"value": 20, "bounds": [0.5, 500], "vary": true},
    "tau_intra": {"value": 100, "bounds": [1, 10000], "vary": true},
    "rise_time_us": {"value": 0.2, "bounds": [0.02, 2], "vary": true},
    "p_y": {"value": 0.5, "vary": false}
  }
}
```

Неуказанные параметры сохраняют умолчания. Порядок переопределений:
умолчания → контракт/лучшая точка предыдущего 2D-фита либо стартовые населённости
1D → явный JSON → CLI. `--bounds` меняет границы, но не переключает `vary`.
Одновременные `--fix` и `--vary` для одного параметра запрещены.

Сначала можно проверить контракт без данных и расчёта:

```bash
../.mars_env/bin/python src/fit_utils/tpe_search_2d.py --print-fit-config \
  --bounds tau_out_x 1 1000 --fix p_y 0.5 --bounds rise_time_us 0.02 2
```

Входной 2D-файл: CSV с полем в первой строке и временем в первом столбце
(умолчания G/ns), числовой NPZ `fields_T/times_s/signal`, либо простой NumPy-PKL
через `DatasetLoader`. Есть `--field-unit`, `--time-unit`, `--signal-key`,
`--dataset`, `--layout`; явные SI-ключи нельзя переобозначить другими единицами.
Не передавай 2D-карту в 1D-фитер и не используй pickle с произвольными классами.

Для первого запуска обязателен `--time-zero-ns`: время приготовления состояния
на экспериментальной оси. Не выводи его из конца предлазерного интервала 0–500 нс.
`--fit-window-ns START STOP` также относится к экспериментальной оси, целиком
после указанного начала. По умолчанию используются все точки начиная с него.
Предлазерные данные остаются в исходном файле для проверки шума.

Числа в примерах параметров демонстрационные. `TIME_ZERO_NS`, имена, данные и
бюджеты подставь из задачи; точное время лазера текущих измерений пока неизвестно.

```bash
../.mars_env/bin/python src/fit_utils/tpe_search_2d.py \
  --input "$DATA_2D" --from-1d "$SLICE_PARAMS_CSV" \
  --time-zero-ns "$TIME_ZERO_NS" --fit-config "$CONTEXT_CONFIG_JSON" \
  --n-trials 300 --name fit2d_global_01 --output-dir results/fits/2d

../.mars_env/bin/python src/fit_utils/cobyla_fit_2d.py \
  --previous-fit results/fits/2d/fit2d_global_01_report.json \
  --budget 300 --name fit2d_local_01 --output-dir results/fits/2d

../.mars_env/bin/python src/fit_utils/fit_2d_context.py \
  --input "$DATA_2D" --from-1d "$SLICE_PARAMS_CSV" \
  --time-zero-ns "$TIME_ZERO_NS" --fit-config "$CONTEXT_CONFIG_JSON" \
  --n-trials 300 --budget 300 --name fit2d_combined_01 --output-dir results/fits/2d
```

`--previous-fit REPORT` (синоним `--tpe-results`) наследует полную лучшую точку,
гамильтониан со strain, базис населённостей, границы, маску, вход, время начала,
окно и масштаб. Контракт TPE
должен оставаться рядом с отчётом. Изменённые байты входных данных вызывают ошибку;
для другого исходника начни новый запуск с `--from-1d`. Между стадиями границы
автоматически не сужаются. У каждой сохранённой версии новый `--name`;
существующие файлы никогда не заменяются.
Старые 2D-отчёты, не фиксирующие T1=eigen и потери=xyz, автоматически не
продолжаются: начни новую версию из 1D, чтобы не подменить прежнюю кинетику.

`--n-trials` ограничивает число TPE-попыток, включая исходную точку;
`--budget` — число оценок локальной цели, включая исходную. Бюджет COBYLA не
меньше числа свободных координат + 2. Кеш повторов может уменьшить число
физических вычислений. При всех фиксированных параметрах выполняется один
расчёт без оптимизатора. Сохраняется лучший допустимый кандидат, включая старт.
Сбой backend не становится штрафом и успешным результатом.

## Цель, результаты и проверки

На **полной постлазерной сетке** рассчитывается MaRS-кинетика и выполняется
единая maxabs-нормировка карты. Затем применяется окно сравнения. Масштаб
фиксируется один раз: по умолчанию max(abs) эксперимента на той же полной сетке,
либо явный положительный `--scale`. `loss_mse_scaled` — средний квадрат
`experiment/scale − normalized_model` в выбранном окне. Это эквивалентно
минимизации noise-K при тех же данных, N, шуме и числе параметров, без добавочного
выравнивания амплитуды/фона. Масштаб не подбирается и свободной координатой не считается.

Каждый запуск сохраняет:

- `<name>_spectrum.npz`: `fields_T`, `times_s` от начала модели, `spectrum` в
  масштабе эксперимента, `normalized_spectrum`, `experimental`, `fit_mask`, метаданные;
- `<name>_params.json`: полный снимок для `check_refit_2d.py`, свободные пути,
  физические границы, линейная связь суммы населённостей и `constraints` для
  границ зависимой населённости. Гамильтониан и уширения среди переменных отсутствуют;
- `<name>_fit_config.json`: контракт со стартом, границами, шкалами и флагами;
- `<name>_report.json`: `optimized_unchecked`, лучшие параметры, loss, счётчики,
  происхождение модели/данных, время начала, окно, масштаб и `n_free_model`.
  При двух стадиях содержит также исходный контракт и метрики TPE.

Для обеих проверок 2D передай **одни и те же** `--fit-key spectrum`,
`--fit-time-offset-ns "$TIME_ZERO_NS"`, `--fit-window-ns "$START_NS" "$STOP_NS"`
из эффективного окна отчёта (`fit_window_s` × 1e9), `--alignment none`,
`--n-parameters "$N_FREE"`. Используй полный исходный `--data` с предлазерным
шумом; для CSV повтори фактические `--csv-field-unit/--csv-time-unit`, а для
многомерного PKL — `--dataset`. Сам снимок не заменяет эти параметры команды.
В независимой проверке используй созданный `<name>_params.json` без правок границ.

Нужны все четыре проверки из spectra-modeling/fit-acceptance: шум, контрольная
доводка, строка текущего фита в сводной таблице и SVG. По
[fit-drawing](../../instructions/fit-drawing.md) передай сохранённый NPZ в
`src/utils/draw_fit_2d.py`: шесть кинетик и шесть временных срезов на одном
`fitdraw_<spectrum_id>.svg`, поля из параметров либо заданные агентом,
времена выбирает агент. Нужен `check_fit_draw_2d.py` с кодом 0/`passed`.
Эти модули таблицу не заполняют
и приёмку не объявляют. Для `T_1` и `lw_Gs` сначала определи физический смысл и
преобразование из модели. При всех параметрах фиксированных текущий контроль
доводкой требует хотя бы одну свободную переменную: такой запуск остаётся
расчётом заданной модели, а не автоматически готовым фитом.
