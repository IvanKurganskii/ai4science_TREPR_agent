# Настройка триплетных фитов

Для подбора 2D-контекста с фиксированными гамильтонианом и уширениями из среза
используй [README_2D.md](README_2D.md): TPE, MaRS Cobyla и обе стадии вместе.
Ниже — контракт трёх **1D**-фитеров.

Общий контракт реализован в `fit_parameters.py`. Он используется всеми тремя
точками входа из корня проекта в существующей среде `../.mars_env`:

| Фитер | Назначение |
|---|---|
| `src/fit_utils/tpe_search.py` | Глобальный поиск Optuna TPE |
| `src/fit_utils/cobyla_fit.py` | Локальный COBYLA: SciPy по умолчанию, `--backend mars` для MaRS/Nevergrad |
| `src/agent_utils/fit_1d_slice.py` | Обе стадии через MaRS SpectrumFitter: Optuna TPE → Nevergrad Cobyla; Dashboard отключён |

Эти инструменты описывают один стационарный триплетный срез, не подбирают 2D-кинетику.
Все используют один симулятор MaRS и MSE после независимой нормировки обоих
спектров на max(abs), сохраняя знак. Число `loss` само по себе не означает
прохождения проверок проекта. Для готовности нужны обязательные проверки
по инструкции моделирования; знаки эмиссии/абсорбции не отбрасываются.

## Параметры по умолчанию

Границы ниже — **границы поиска**, а не условия приёмки. Агент может самостоятельно
выбрать другие границы, стартовые значения и свободные/фиксированные параметры
перед очередным запуском; править код для этого не требуется.

| Имя | Начальное значение | Границы | Варьируется |
|---|---|---|---|
| `g_iso` | 2.0023 | [2.0,2.12] | да |
| `D` | 1.5e9 Hz | **[5e8,3e9] Hz = [500,3000] МГц** | да |
| `E` | 2e7 Hz | [5e6,4e7] Hz | да |
| `ham_strain` | 0 Hz | [0,1e8] Hz | нет |
| `gauss` | 1e-4 T | [1e-5,5e-4] T | да |
| `lorentz` | 0 T | [0,5e-4] T | нет |
| `pop_x`, `pop_y`, `pop_z` | 0.2,0.5,0.3 | каждый [0,1], сумма 1 | да, две независимые координаты |
| `freq` | 9.8e9 Hz | не заданы | нет |
| `temperature` | 10 K | не заданы | нет |
| `basis` | `xyz` | xyz/product/eigen/zfs/multiplet/zeeman | нет |

У `fit_1d_slice.py` исходное умолчание температуры — 80 K; явный JSON/CLI
имеет приоритет. `freq` и `temperature` также можно варьировать, задав границы.
Не включай неидентифицируемые параметры без обоснования: при явно заданных
населённостях температура не управляет их стационарным распределением.
Для всех частотных параметров используй **Hz**, для ширин **T**; например
500 МГц = `5e8` Hz, 1 Гс = `1e-4` T. Имена `p_x/y/z`, `px/py/pz` принимаются
как алиасы `pop_x/y/z`; скалярный `g` — как алиас `g_iso`.

`harmonic` и `mesh` — настройки расчёта, не оптимизируемые физические параметры.
Выбирай их через `--harmonic`/`--mesh` или `settings` в JSON и сохраняй одинаковыми
для сравниваемых запусков. Умолчания: harmonic 0 (абсорбция/эмиссия), mesh 20,
минимальная сетка 5. Гармоника 1 означает первую производную.

## Общие опции всех трёх CLI

| Опция | Действие |
|---|---|
| `--fit-config PATH` | Прочитать JSON с параметрами и настройками |
| `--bounds PARAM LOW HIGH` | Задать числовые границы; можно повторять для разных параметров |
| `--initial PARAM VALUE` | Задать начальное значение, сохранив текущий флаг vary |
| `--fix PARAM VALUE` | **Выключить вариацию**, зафиксировав значение |
| `--vary PARAM` | **Включить вариацию** с выбранными границами/вариантами |
| `--print-fit-config` | Вывести итоговую конфигурацию, не читая спектр и не запуская фит |

Выключенный параметр остаётся в модели с фиксированным значением, а не исчезает.
Чтобы убрать вклад уширения, задай его значение 0; при этом хотя бы один из
`gauss/lorentz/ham_strain` должен оставаться положительным. Например:

```bash
../.mars_env/bin/python src/fit_utils/tpe_search.py --print-fit-config \
  --bounds D 5e8 3e9 --bounds E 0 3e8 \
  --fix ham_strain 0 --fix basis xyz --vary gauss
```

Для категории `basis` числовые границы не используются: `choices` задаётся в JSON.
Все три 1D CLI принимают `--basis`; базис и числа населённостей сохраняются вместе.
Список вариантов по умолчанию при включении vary остаётся xyz/product; другие
разрешённые варианты добавь в `choices`. При явном выборе нового значения без
`choices` оно добавляется в разрешённый список. Выбор значения через `--basis`
не переключает флаг vary; для фиксации используй `--fix basis VALUE`.
`--fix basis xyz` оставляет один базис; `--vary basis` разрешает выбранные варианты.
TPE выбирает категорию; локальный COBYLA перебирает базисы с отдельным непрерывным
подбором, разделяя **общий** бюджет. Одновременные `--fix` и `--vary` одного
параметра — ошибка; неоднозначные/неизвестные имена и нечисловые границы отклоняются.

Фиксированное значение не ограничивается неиспользуемыми границами поиска, но
должно быть физически допустимым. Если новые границы исключают начальную точку
**варьируемого** параметра, старт прижимается к ближайшей границе. Это новая
стартовая точка, а не исправление старого результата: изучи `--print-fit-config`
до расчёта. При изменении начальных населённостей корректируются только свободные
населённости до совместимой точки; фиксированные значения сохраняются.

## JSON-конфигурация

Файл можно сохранить в новом каталоге запуска внутри `results/`. Пример:

```json
{
  "schema_version": 1,
  "parameters": {
    "D": {"value": 1500000000, "bounds": [500000000, 3000000000], "vary": true},
    "E": {"value": 20000000, "bounds": [0, 300000000], "vary": true},
    "g_iso": {"value": 2.0023, "bounds": [1.95, 2.1], "vary": true},
    "gauss": {"value": 0.0001, "bounds": [0.000001, 0.001], "vary": true},
    "ham_strain": {"value": 0, "bounds": [0, 100000000], "vary": false},
    "lorentz": {"value": 0, "bounds": [0, 0.0005], "vary": false},
    "pop_x": {"value": 0.2, "bounds": [0, 1], "vary": true},
    "pop_y": {"value": 0.5, "bounds": [0, 1], "vary": true},
    "pop_z": {"value": 0.3, "bounds": [0, 1], "vary": true},
    "basis": {"value": "xyz", "choices": ["xyz", "product"], "vary": false},
    "freq": {"value": 9800000000, "vary": false},
    "temperature": {"value": 80, "vary": false}
  },
  "settings": {"harmonic": 0, "mesh": 25}
}
```

Неуказанные параметры и поля получают умолчания. Перед включением вариации
freq/temperature добавь конечные положительные `bounds`. `vary` — только
JSON true/false; None, NaN и Inf недопустимы. Для фиксации используй vary=false,
не равные границы. Требуются `low < high` и допустимая начальная модель.

Приоритет от низшего к высшему: умолчания → сохранённый контракт TPE и его
лучшие значения → `--fit-config` → явные CLI-значения/границы/флаги.
Старые ручные опции COBYLA (`--g-iso`, `--D`, `--E`, `--ham-strain`, `--gauss`,
`--lorentz`, `--pop-x/y/z`, `--basis`) задают значения, не меняя сами флаг vary.

## Населённости и зависимости

Границы относятся к **фактическим нормированным** населённостям, а не к трём
сырым весам до нормировки. Фиксированные населённости никогда не масштабируются
ради суммы. Оставшаяся масса распределяется между свободными в их границах.
Несовместимые ограничения отклоняются до фита, например три нижних границы 0.4.

Последняя свободная населённость в порядке x,y,z вычисляется из суммы 1.
Поэтому при трёх/двух/одной свободных населённостях независимых координат 2/1/0.
Это также работает при фиксации любой из трёх, а не только p_z. Если фиксированы
все три, их сумма должна быть 1. Если все параметры фиксированы, модель
вычисляется один раз на стадию без вызова оптимизатора; при нескольких базисах —
по разу на базис. `n_free_model` учитывает независимые модельные координаты и
выбираемый базис, но не дополнительную калибровку амплитуды проверяющим скриптом.

В `product` три компоненты означают p_+,p_0,p_-, а не молекулярные px/py/pz.
Физические ограничения `|E| <= |D|/3`, конечность, допустимость уширений и
населённостей действуют при любых выбранных границах. Невозможные кандидаты
штрафуются; при отсутствии валидного ненулевого результата фит не сохраняется.

## Запуск и перенос между стадиями

Сначала задай фактические пути `SLICE_CSV`, `CONFIG_JSON`, новый `RUN_ID` и
бюджеты. Каждый запуск получает новый каталог; фиксированные имена выходов
внутри одного каталога могут быть перезаписаны повторным вызовом.

```bash
../.mars_env/bin/python src/fit_utils/tpe_search.py \
  --input "$SLICE_CSV" --field-unit G --fit-config "$CONFIG_JSON" \
  --n-trials 500 --seed 42 --output-dir "results/fits/1d/$RUN_ID/tpe"

../.mars_env/bin/python src/fit_utils/cobyla_fit.py \
  --input "$SLICE_CSV" --field-unit G \
  --tpe-results "results/fits/1d/$RUN_ID/tpe/tpe_best_params.csv" \
  --budget 300 --output-dir "results/fits/1d/$RUN_ID/cobyla"

../.mars_env/bin/python src/agent_utils/fit_1d_slice.py \
  --slice "$SLICE_CSV" --field-unit G --fit-config "$CONFIG_JSON" \
  --n-trials 300 --budget 300 --seed 42 \
  --output-dir "results/fits/1d/$RUN_ID/mars"
```

Последняя команда — самостоятельная альтернатива первым двум. Все входы:
CSV с комментариями и двумя строками (поле, интенсивность), числовой NPY `(N,2)`
или NPZ `field/intensity`. Поле по умолчанию G в CSV, T в NPY/NPZ; при другом
выборе укажи `--field-unit T|mT|G|uT`. Pickled NPY не поддерживается.
Формат канонических NPZ `mars_cleaning/mars_simulation` отличается: сначала
получи срез и явно согласуй имена ключей, не передавай 2D-карту как 1D.

COBYLA наследует `fit_config`, указанный в CSV TPE: границы, фиксированные значения,
vary-флаги и настройки. Лучшие значения CSV становятся стартом; явные новые
опции переопределяют их. Переноси CSV **вместе с** его конфигурацией; потерянный
ссылочный JSON вызывает ошибку. Для старого CSV без контракта применяются
новые умолчания: при необходимости явно восстанови прежние границы/маску.
Границы между стадиями автоматически не сужаются. Для локального шага нужен
бюджет не меньше `число непрерывных координат + 2` на каждый базис; при всех
числах фиксированных — один вызов на базис. Бюджет общий для перечисленных базисов.

## Результаты

| Фитер | Основные файлы |
|---|---|
| TPE | `tpe_best_params.csv`, `tpe_best_spectrum.npz`, `tpe_fit_config.json` |
| COBYLA | `cobyla_fit_results.csv`, `cobyla_best_spectrum.npz`, `cobyla_fit_config.json` |
| MaRS обе стадии | `<name>_params.json`, `<name>_params.csv`, `<name>_spectrum.npz`, `<name>_fit_config.json`, `<name>_report.json` |

Контракт JSON хранит фактические границы, **начальные** значения, фиксированные
параметры, флаги и настройки стадии. CSV/params.json хранят **полную лучшую**
модель, включая фиксированные и зависимые значения; они не восстанавливаются
только из `study.best_params` или позиции в векторе. CSV содержит loss,
масштаб, `n_free_model`, число оценок и ссылку `fit_config`.

NPZ содержит поле в T, `simulated` (сырой расчёт), `intensity` (масштабированный
к max(abs) эксперимента), `experimental`, нормированные массивы и метрики.
Для шумовой проверки выбирай `--fit-key intensity`. MaRS-обёртка отмечает
результат `optimized_unchecked`: проверки приёмки выполняются отдельно.
Для итогового рисунка передай NPZ в `src/utils/draw_fit_1d.py` по
[fit-drawing](../../instructions/fit-drawing.md); нужен SVG наложения и успешный
`check_fit_draw_1d.py` вместе с шумом, доводкой и таблицей.
Лучший допустимый результат, включая старт локального подбора, сохраняется даже
при остановке COBYLA по бюджету; последнее предложение оптимизатора не заменяет
лучший проверенный кандидат.

Конфигурация поиска не изменяет условия приёмки из
[fit-acceptance.md](../../instructions/fit-acceptance.md). Текущий независимый
адаптер поддерживает ham_strain и выбранный фиксированный `population_basis`;
вариация частоты/температуры и категориальный поиск базиса в контрольной COBYLA
не поддерживаются. При сравнении базисов оформляй отдельные версии фита.
Проверяй совместимость до подбора; не удаляй физические параметры и не фиксируй
их лишь ради прохождения проверки. Полный снимок и границы для контрольной
доводки должны воспроизводить именно сдаваемую модель.
