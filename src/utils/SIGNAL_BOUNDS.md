# Границы сигнала

`signal_bounds.py` читает 1D-трассу или 2D-карту и возвращает компактный JSON.
Входы сохраняются без изменений; срезание/очистка и создание новых спектров
не выполняются. Для записи отчёта укажи новый `--report`; без него только stdout.
Родительский каталог отчёта должен существовать; файл не перезаписывается.

## Алгоритм и параметры

- Первые `--noise-points 10` отсчётов задают исходный фон. Из интенсивности
  вычитается среднее этого блока. Уровень шума A — максимум абсолютного отклонения.
- Ищутся `--min-run 3` последовательных точек с отклонением **строго больше**
  `--factor 3` × A. Граница — первая точка подтверждённой серии при обходе с края,
  а не точка, на которой завершилось подтверждение.
- `--direction forward` ищет начало слева; `backward` — конец справа; `both`
  выполняет оба поиска. Для правого края шум оценивается по последним 10 точкам.
- Фон/шум конца сравниваются с начальным блоком. Если отличие среднего или
  величина конечного шума превышают начальный порог, конец остаётся неустановленным:
  причиной могут быть остаточный сигнал, дрейф фона или неоднородный шум.
- `--margin 3` добавляет запас в отсчётах к `padded_index/padded_coordinate`;
  собственно обнаруженные границы, пики и координаты от него не меняются.
- Для нулевой оценки шума используется численная погрешность и необязательный
  `--noise-floor` (минимальный уровень шума перед умножением на factor).

Предполагается, что начальный блок действительно находится вне сигнала.
По одним десяти точкам это доказать нельзя. Один выброс в опорном блоке завышает
максимум и делает поиск консервативным. При необходимости выбери другой размер
шумового блока, предварительно устрани подтверждённые выбросы/фон, сохрани настройки.
Детектор находит обнаруживаемую часть сигнала, а не физически точный момент
возникновения/исчезновения слабого хвоста. min-run выбирай по дискретизации,
чтобы не пропустить узкую настоящую линию.

## Форматы и 2D

Запуск из корня проекта в существующей среде `../.mars_env`:

```bash
../.mars_env/bin/python src/utils/signal_bounds.py \
  --input "$SLICE_CSV" --peak-candidates \
  --report "$NEW_BOUNDS_JSON"
```

По умолчанию `--kind 1d --axis field --direction both`. Поддерживаются
двухстрочный CSV (координаты, интенсивности; комментарии #), числовой NPY `(N,2)`
и NPZ. У NPZ поле — `fields_T/field`, время — `times_s/time/times`; сигнал —
`intensity/spectrum/signal/experimental/simulated` либо явный `--signal-key`.
CSV по умолчанию использует G для поля и ns для времени, NPY/NPZ — T/s.
Есть `--field-unit T/mT/G`, `--time-unit s/ms/us/ns/ps`; противоречащая явно
сохранённым единицам NPZ опция вызывает ошибку. 1D-ось должна строго возрастать.

Для `--kind 2d` используется существующий `DatasetLoader`: канонический NPZ
`fields_T/times_s/signal`, CSV-матрица с полем G в первой строке и временем ns
в первом столбце либо простой NumPy-PKL. Для нескольких наборов нужен `--dataset`;
другой ключ сигнала задаётся `--signal-key`, порядок осей — `--layout`.

```bash
# Начало/конец по времени, используя выбранную область поля:
../.mars_env/bin/python src/utils/signal_bounds.py \
  --input "$DATA_2D" --kind 2d --axis time \
  --field-window-T "$B_MIN_T" "$B_MAX_T" --report "$NEW_TIME_BOUNDS_JSON"

# Область сигнала по полю в выбранном временном интервале:
../.mars_env/bin/python src/utils/signal_bounds.py \
  --input "$DATA_2D" --kind 2d --axis field \
  --time-window-ns "$START_NS" "$STOP_NS" --peak-candidates
```

У 2D среднее фона вычитается **отдельно в каждом канале**, затем строится
профиль `--aggregation rms` или `maxabs` по другой оси. Знаковые a/e-компоненты
не усредняются друг с другом. Если окно другой оси не задано, берутся все каналы.
Для формул D/g нужен поиск **по полю**, не по времени.

## Результат

- `boundaries.left/right`: найденный индекс/координата, дополненная запасом
  граница, точка подтверждения, статистика собственного шумового блока и порог.
- `threshold_span` — расстояние между пороговыми границами;
  `threshold_midpoint` — их полусумма. Это не расстояние/центр подтверждённых Z-пиков.
- `edge_comparison`, `warnings`: совместимость фоновых блоков и ограничения оценки.
- С `--peak-candidates` дополнительно возвращаются первые/последние выраженные
  локальные максимумы модуля отклонения (для 2D — профиля). Требуются высота и
  prominence не ниже порога, кандидат должен лежать в серии длиной min-run.
  SciPy нужен только для этой опции. `edge_peak_candidates` хранит координаты,
  расстояние и полусумму для двух различных кандидатов. Поле
  `confirmed_z_peaks` всегда false: физическое назначение проверяется отдельно.
  В 1D polarity a/e относится к заданному пользователем фазовому соглашению.

Координаты CLI всегда в SI: T либо s. Индексы с нуля; после 2D-импорта они
относятся к канонической возрастающей оси `DatasetLoader`, а не к возможному
обратному порядку строк исходного файла. Массивы и поканальные фоновые векторы
в JSON не выводятся. Источник сопровождается SHA256.

Код 0, `found`: все запрошенные пороговые границы найдены. Код 1:
`partial/not_found/inconsistent`; отсутствующие координаты равны null,
границы записи не подставляются. Код 2, `invalid`: ошибка формата, NaN/Inf,
неподходящая длина, настройки или путь отчёта. Для both/backward нужны
как минимум `2*noise_points+min_run` отсчётов; для forward — `noise_points+min_run`.
Статус границ не подтверждает, что найдены Z-пики; для них проверяй отдельный статус.

Python API: `find_signal_bounds(axis, intensity, sample_axis=0, ...)`.
Для 2D ось `sample_axis` соответствует axis, вторая ось содержит каналы.
См. [короткую инструкцию фита](../../instructions/fit-slice.md) для применения к D/g.
