# Проверка фита по предлазерному шуму

Точки входа: [check_fit_1d.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_1d.py) и [check_fit_2d.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_2d.py).
Общая реализация — [fit_noise.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/fit_noise.py). Требуется NumPy и приватный
загрузчик `check_support` из внешней папки checks; MaRS, оптимизатор и сеть при проверке не запускаются.

Скрипты читают данные и выдают JSON. Исходные спектры, срезы и результаты фита
не изменяются. Опция `--report` сохраняет новый JSON-файл внутри проекта;
существующий файл, включая входной, не перезаписывается. Каталог отчёта должен
существовать. Пути разрешаются относительно явно переданного `--root`; без этой опции используется текущая
директория. В командах проекта всегда передавай `--root "$PWD"`.

## Метрика и допуск

Для каждого магнитного поля на предлазерном участке подбирается прямая по времени.
Пусть после проекции на окно среза осталось M временных блоков и B полевых точек.
Оценка средней дисперсии шума:

`noise_variance = sum((noise - linear_background)**2) / ((M - 2) * B)`.

Для N точек основного фита и p независимо подобранных параметров:

`K = (sum((measured - fitted)**2) / (N - p)) / noise_variance`.

Среднее основных остатков перед вычислением суммы квадратов не вычитается:
постоянная систематическая ошибка тоже должна влиять на результат. В отчёте есть
K, `sqrt(K)`, RMSE, среднее остатков, число точек/степеней свободы, корреляции
соседних точек по времени/полю и SHA-256 входных файлов.

Точного совпадения остатков с шумом и равенства K единице не требуется.
Допуск задаётся заранее через `--max-k`: проверка принимает K <= Kmax.
Порог не подбирают после просмотра результата, чтобы принять неудачный фит.
Универсальное значение Kmax не установлено. Без `--max-k` скрипт рассчитывает
метрики, но возвращает `diagnostic`, а не успешную приёмку.

SVD, сглаживание, неодинаковый шум по полю и нелинейный подбор ограничивают
статистическую интерпретацию. Неперекрывающиеся блоки не объявляются независимыми.
Поэтому скрипты не выдают формальный F-test p-value и не используют номинальное
число степеней свободы для автоматической приёмки. Корреляции — диагностика,
а не самостоятельный критерий годности. Сохраняемые степени свободы номинальные.

Математическая основа: [остаточная дисперсия NIST](https://www.itl.nist.gov/div898/handbook/pri/section6/pri619.htm),
[условия F-распределения](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.f.html).

## Фоновый интервал

Точное положение вспышки на временной оси не установлено. Пользователь подтвердил,
что для текущих четырёх измерений она происходит позже 500 нс. Поэтому при их
проверке указывается `--noise-window-ns 0 500`. Это утверждение о безопасном
предлазерном участке, а не установка момента вспышки в 500 нс. Для новых измерений
интервал подтверждается отдельно. Автоматического выбора времени вспышки нет.

Окно основного фита не должно пересекаться с шумовым. Для 2D точки из предлазерного
интервала и более ранние исключаются из основного RSS; фактическое окно указывается
в отчёте. `--fit-window-ns START STOP` дополнительно ограничивает область сравнения.

## 1D: происхождение среза и перенос шума

Сейчас в восьми CSV-срезах есть `Processed spectrum` и `Integration time range`.
Указанные обработанные 2D-файлы существуют. Диапазоны имеют равные начало и конец:
нынешние срезы — отдельные временные кадры. Это подтверждается логикой
`src/recreate_slices.py`, хотя его заголовки называют операцию интегрированием.
Численная оценка шума, его дисперсия и ковариация в шапках не сохранены.
Пути `Source` к сырым файлам устарели и не совпадают с существующими именами.

Автоматически используется родитель из `results/spectra/processed/`, указанный в
`Processed spectrum`. Нет выбора сырого файла по похожему имени. Для другого
расположения нужен `--source-2d`. Численно проверяется, что родитель с указанным
окном и операцией воспроизводит срез с допуском округления.

- Равные границы окна означают `point`: переносится шум одного кадра.
- Для ненулевого окна обязателен `--slice-operation mean`, `sum` или `integral`.
- `integral` использует правило трапеций; обязателен `--integration-unit ns`
  (либо s/ms/us/ps), чтобы сохранить фактические единицы амплитуды среза.
- На предлазерном участке берутся неперекрывающиеся блоки с тем же числом точек,
  временными шагами и весами, что у среза. Шум оценивается после этой операции;
  деление исходного sigma на sqrt(n) без проверки независимости не используется.
- Необходимы минимум три полных блока. Если фон короче, сравнение считается
  недоступным; нельзя уменьшать окно реального среза ради прохождения проверки.
- Для сохранённого линейного нормирования среза укажи `--slice-scale` и
  `--slice-offset`. Масштаб одинаково применяется к проверке происхождения и шуму.
- При неполной шапке окно можно явно передать через `--slice-window-ns START STOP`.

Ниже `SLICE_CSV`, `FIT_NPZ`, `N_FREE`, `K_MAX` обозначают значения из текущей задачи;
их нужно задать до вызова. Числовой порог этим примером не устанавливается.

```bash
../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_1d.py" --root "$PWD" \
  --slice "$SLICE_CSV" --fit "$FIT_NPZ" \
  --noise-window-ns 0 500 --n-parameters "$N_FREE" --max-k "$K_MAX"
```

## 2D

`--data` задаёт измеренный 2D-спектр с сохранённой предлазерной областью, в тех же
единицах амплитуды и после той же обработки, что использована в фите. Оценивается
шум на тех же полевых точках, что присутствуют в сохранённой симуляции. Модель
может покрывать подмножество измеренных времён и полей. Полные числовые массивы
в ответ не выводятся.

```bash
../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_fit_2d.py" --root "$PWD" \
  --data "$DATA_2D" --fit "$FIT_NPZ" \
  --noise-window-ns 0 500 --n-parameters "$N_FREE" --max-k "$K_MAX"
```

Если модельное время задано относительно собственного начала, явно укажи
`--fit-time-offset-ns`; оно прибавляется к времени симуляции перед сопоставлением
с измерением. Точное время лазера из этой опции автоматически не выводится.

## Форматы и единицы

- 1D-измерение: CSV с комментариями, затем две строки — поле и интенсивность.
- 2D-измерение: существующий формат CSV с полем в первой строке и временем в
  первом столбце; либо канонический NPZ/ограниченный NumPy-PKL загрузчика
  `mars_cleaning.data.DatasetLoader`. Для нескольких наборов нужен `--dataset`.
- По умолчанию у старых CSV поле в G, время в ns. Для другого формата укажи
  `--csv-field-unit` / `--csv-time-unit`; они не меняют явные SI-ключи NPZ.
- 1D-симуляция: NPZ с `fields_T` либо legacy-ключом `field` (оба в T) и
  `simulated`, `fitted` либо `spectrum`. При другом имени есть `--fit-key`.
- 2D-симуляция: NPZ с `fields_T`, `times_s` и `spectrum`/`fitted`/`simulated`;
  порядок массива строго `(time, field)`. Поддерживается также осевой 2D CSV.
- Для 1D-симуляции в двухстрочном CSV доступен `--fit-field-unit`.
- Числовые сетки сопоставляются с допуском округления; скрытой интерполяции,
  экстраполяции и угадывания единиц по величине поля нет.
- Старый `tpe_search.py` сохраняет словарь в pickled `.npy`; этот формат проверка
  не открывает. Для проверки сохраняй числовой NPZ с полем и симуляцией.

При отсутствии масштаба симуляции можно явно выбрать `--alignment scale` либо
`affine`: масштаб/смещение подбираются МНК по всей области сравнения. Они выводятся
в отчёт и добавляют соответственно 1 или 2 свободных параметра. По умолчанию
`none`: скрипт сравнивает сохранённые амплитуды без дополнительной подгонки.

`--n-parameters` включает все независимо подобранные параметры модели и прежнего
нормирования, но не повторно параметры, добавляемые текущим `--alignment`.
Фиксированные параметры не считаются; например, три населённости с установленным
ограничением суммы имеют два независимых параметра. Общие параметры нескольких
срезов считают по реальной схеме совместного подбора; одна проверка отдельного
среза не доказывает качество всего совместного фита.

## Статусы

- Код 0, `passed`: метрика рассчитана и соответствует заданному верхнему допуску K.
- Код 1, `failed`: расчёт корректен, K превышает заданный допуск.
- Код 2, `diagnostic`: метрики рассчитаны, порог приёмки не задан.
- Код 2, `invalid`: входы/единицы/происхождение/размеры некорректны, шум вырожден,
  недостаточно точек либо возникла ошибка. Такой результат не считается приёмкой.

`passed` относится к этой проверке, а физический смысл модели и структуру остатков
оценивают вместе с остальными критериями задачи. При исчерпанном бюджете сохраняй
фактический статус, а не меняй допуск или исходные данные для получения кода 0.
