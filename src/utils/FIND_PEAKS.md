# Максимумы и минимумы 1D-сигнала

`find_peaks.py` находит локальные экстремумы знакового сигнала. Скрипт возвращает
числа; назначение X/Y/Z, a/e, выбор базиса и оценка D/E остаются за агентом.
Точки перегиба не ищутся. Данные не сглаживаются, не нормируются и не изменяются.

## Запуск

Из корня проекта в существующей среде:

```bash
../.mars_env/bin/python src/utils/find_peaks.py \
  --input "$SLICE_CSV" --report "$NEW_PEAKS_JSON"

# Только пики внутри ранее найденных границ, координаты в T:
../.mars_env/bin/python src/utils/find_peaks.py \
  --input "$SLICE_CSV" --range "$B_LEFT_T" "$B_RIGHT_T" \
  --prominence 0.05 --min-width 3 --distance 3
```

`0.05` — пример порога в единицах интенсивности, не универсальная настройка.
`--report` необязателен; без него новых файлов нет. Каталог отчёта должен
существовать, путь должен быть новым: перезапись запрещена.

## Вход

- CSV: ровно две числовые строки — координата, интенсивность; поле по умолчанию G.
- NPY: числовой массив `(N,2)`, по умолчанию поле в T.
- NPZ: ось `fields_T`/`field`, сигнал `intensity`, `spectrum`, `signal`,
  `experimental` или `simulated`; другой ключ задаётся через `--signal-key`.
- `--field-unit T|mT|G` задаёт единицы входа; противоречие явным единицам NPZ — ошибка.

Нужны конечные вещественные 1D-векторы одинаковой длины и строго возрастающая ось.
Для 2D сначала получи срез. Отрицательные поля не принимаются.
Выходные координаты и `--range` всегда в **T**, независимо от единиц входа.
Для временной трассы есть `--axis time` и `--time-unit s|ms|us|ns|ps`;
CSV по умолчанию в ns, NPY/NPZ в s, ось NPZ `times_s`/`time`/`times`, выход в s.

## Поиск и фильтры

Максимумы ищутся по интенсивности после вычитания постоянного фона, минимумы —
по её отрицанию. Фон — среднее первых `--noise-points 10` исходных отсчётов;
предполагается, что они находятся вне сигнала. Оценка шума A — максимальное
абсолютное отклонение этого блока от среднего. Один выброс завышает A.

По умолчанию и минимальная выраженность (prominence), и минимальное абсолютное
отклонение от фона равны `--factor 3` × A. При нулевом/очень малом шуме применяются
численный порог и `--noise-floor 0`. `factor` должен быть больше 1.

- `--prominence`: независимый порог выраженности пика в единицах интенсивности.
- `--min-abs-height`: независимый порог абсолютного отклонения от фона;
  помогает отсеять почти нулевые промежутки между линиями одного знака.
- `--min-width 3`: минимальная ширина на половине prominence, в отсчётах.
  Это не автоматически физическая FWHM линии; узкий реальный пик может потребовать
  меньшего порога.
- `--distance 3`: расстояние между пиками одного типа, в отсчётах.
  Соседние максимум и минимум этим фильтром друг друга не удаляют.
  SciPy применяет расстояние до фильтра ширины; близкие кандидаты могут подавляться.
- `--extrema both|maxima|minima`: какие типы искать.

Для всех локальных экстремумов без этих фильтров используй
`--prominence 0 --min-abs-height 0 --min-width 0 --distance 1`.
Это возвращает также экстремумы шума. Первые/последние точки записи пиками
не считаются: для экстремума нужны соседи с обеих сторон. Плоская вершина даёт
один пик в середине плато (при чётной длине — левее середины).

`--range START STOP` фильтрует координаты готовых кандидатов включительно.
Соседи, шумовой блок, prominence и ширина берутся по исходной трассе;
границы диапазона не создают искусственных пиков. Пороги и настройки фильтров
сохраняются в отчёте; автоматического выбора «шести нужных пиков» нет.

## Результат и экономия контекста

JSON содержит статус, общее количество и раздельные числа максимумов/минимумов,
настройки, оценку фона/шума, путь и SHA256 входа. Список `peaks` отсортирован
по возрастанию поля. Каждый элемент содержит:

- `index` (с нуля в исходном файле), `coordinate`, `kind=maximum|minimum`;
- исходную `intensity` и отклонение от фона `relative_intensity`;
- `prominence`, `width_points`, `width_axis` (T или s);
- `plateau_indices`, если вершина плоская.

Тип экстремума и знак независимы: минимум может лежать выше фона, максимум —
ниже. `kind` сам по себе не обозначает a/e или физический переход.

В терминале по умолчанию не более `--max-output-peaks 20` элементов. При усечении
`output_complete=false`, `n_output_peaks` — размер вывода, `n_peaks` — полный счёт.
Не делай разметку по неполному списку. Полный JSON в `--report` и результат Python
API сохраняют все найденные пики. При множестве кандидатов сначала уточни фильтры
или просматривай нужный диапазон отчёта; исходные массивы в контекст не выводи.

Коды завершения: `0` — есть пики, `1` — пиков нет, `2` — ошибка входа/параметров.

Python API: `from src.utils.find_peaks import find_extrema`;
`find_extrema(fields_T, intensity, coordinate_range=(left_T, right_T))`.
Ключи API: `min_prominence`, `min_abs_height`, `min_width`, `distance`, `extrema`,
`noise_points`, `factor`, `noise_floor`, `axis_kind`, `axis_unit`.
API не конвертирует единицы: для поля передавай T, для времени — s.
