Точки входа: [check_refit_1d.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/check_refit_1d.py) для среза и
[check_refit_2d.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/check_refit_2d.py) для временно-полевой карты.
Приватные адаптеры данных и симуляции находятся в `checks/check_support/`; код проекта не импортируется. Реализация — [fit_refinement.py](C:/Users/kurga/OneDrive/Документы/YSDA/checks/fit_refinement.py).

Обе проверки используют интерфейс **MaRS**, доступный в существующей среде
`../.mars_env`: `SpectrumFitter` или `Spectrum2DFitter` и
`fit(backend="ng", optimizer="Cobyla", budget=500)`. Это оптимизатор Nevergrad,
подключённый через MaRS; собственный вызов `scipy.optimize.minimize` не используется.
Внутренние зависимости Nevergrad этим утверждением не ограничиваются.

## Окружение и дополнительные зависимости

В рабочей папке используются две среды:
`../.mars_env` с Python 3.11/MaRS и `../AI4Science/.venv` с Python 3.14 для
обвязки/MCP. Во второй нет MaRS и научных библиотек. Для расчётов используется
первая, указанная в AGENTS.md.

Для публичного модуля оптимизации MaRS нужны `tqdm`, `nevergrad`, `optuna`,
`optuna-dashboard`, `emcee`, `numdifftools`, `optuna-integration` и `hdbscan`. Optuna и
Optuna-integration используют ветку 4.x под интерфейс установленной MaRS.
`numdifftools` и `optuna-integration` нужны из-за импортов namespace, хотя
метаданные этой версии MaRS описывают их не полностью. Hdbscan импортируется
модулем SpaceSearcher при загрузке namespace, хотя сам контроль кластеризацию
не запускает. Plotly для Cobyla не нужен.

Проверяющий скрипт предварительно проверяет наличие модулей и возвращает `invalid`,
если их нет. Интеграционные тесты требуют готовую среду и явно пропускаются при
отсутствии зависимостей; пропуск не подтверждает работу оптимизатора. Агент сам
не устанавливает пакеты вопреки границам AGENTS.md.

## Что проверяется

1. Выполняется [проверка шума](FIT_CHECKS.md), включая происхождение среза и
   предлазерный интервал. Для текущих измерений подтверждён участок 0–500 нс.
2. По полному снимку модели заново вычисляется спектр. Он должен воспроизводить
   сохранённый ответ агента с численным допуском `--spectrum-rtol` относительно
   максимума абсолютной интенсивности; по умолчанию допуск равен 1e-5.
3. Из параметров агента запускается MaRS Cobyla с теми же границами и связями.
   Все независимо варьируемые параметры переводятся во внутренний диапазон 0–1.
   Начальная точка задаётся через `ParamSpec.default` и проверяется при первом вызове.
4. Отслеживается лучший допустимый результат, включая исходную точку. Нельзя
   принять результат только потому, что итоговая рекомендация оптимизатора хуже.

Для 2D модель и её нормирование вычисляются на полной сохранённой временной
сетке; только затем применяется окно сравнения. Это сохраняет исходное начало
кинетического расчёта и масштаб `maxabs` при исключении ранних точек.

Сравнивается тот же K, что в проверке шума. Шум, N, число свободных параметров,
область данных и способ нормирования фиксированы на протяжении контроля.
В снимке явно указывается `objective: "noise_k"`. Основной подбор должен решать
эту же задачу либо эквивалентную ей MSE при том же нормировании. Если агент
подбирал по другой функции, такой контроль нельзя выдавать за продолжение того же фита.
Начальный K пересчитывается по заново сгенерированному спектру; заявленная агентом
метрика не используется как доверенное значение.

Условие устойчивости:

`initial_K - best_K <= improvement_atol + improvement_rtol * initial_K`.

Оба допуска явно задаются до основного подбора; требуется хотя бы один ненулевой.
Таким образом, небольшое численное улучшение допускается. Полная приёмка требует
также `initial_K <= max_K` из проверки относительно шума. Параметры критерия нельзя
менять после получения ответа ради прохождения контроля.

Контроль локальный и ограничен бюджетом. Отсутствие улучшения не доказывает
глобальный минимум или однозначность физических параметров.

## Бюджет и время

- `--budget 500` — предел вызовов цели оптимизатором; первичное воспроизведение
  спектра выполняется дополнительно. Повторные физические симуляции кешируются.
- `--time-limit-seconds 300` — предел времени всего дочернего процесса, включая
  загрузку MaRS, проверку исходов и первичную симуляцию. Оба значения настраиваются.
- В установленной MaRS цикл `fit_nevergrad` не реализует переданный `timeout`.
  Поэтому временем управляет отдельный родительский процесс; в WSL при превышении
  лимита завершается группа проверочного процесса. До запуска учитывается остаток
  общего бюджета эпизода из AGENTS.md.
- Тайм-аут, отсутствие backend, неверные параметры и авария имеют ненулевой код
  завершения и не становятся успешной приёмкой.

Полные исходные массивы, параметры и спектр агента не перезаписываются.
`--report` записывает отдельный новый JSON; существующий файл не заменяется.
Отчёт содержит исходные/лучшие параметры, K, улучшение, допуск, число вызовов,
отклонённые недопустимые точки, время, backend и хеши входов. В терминал выводится
короткий JSON без массивов и полных списков параметров.

## Снимок модели

`--parameters` задаёт JSON с моделью `high_j` или `moderate_j`, точными аргументами
существующего `SimulationEngine`, исходным калибровочным масштабом/смещением и
перечнем свободных параметров с границами. Снимок нужно сохранить вместе с
основным фитом. Одна таблица g/D/E без условий эксперимента и населённостей
недостаточна для воспроизведения спектра.

Ниже только пример формата. Частота, сетка, нормирование, параметры и границы
должны соответствовать фактическому основному фиту:

```json
{
  "model": "high_j",
  "dimension": "1d",
  "objective": "noise_k",
  "simulation": {
    "hamiltonian": {
      "g": 2.0023, "D": 120000000, "E": 20000000,
      "gauss": 0.0006, "lorentz": 0.0
    },
    "settings": {
      "freq": 9800000000, "temperature": 80,
      "mesh": 5, "dtype": "float64", "device": "cpu"
    },
    "populations": {"p_x": 0.2, "p_y": 0.7, "p_z": 0.1},
    "population_mode": "raw", "normalization": "none"
  },
  "calibration": {"scale": 1.0, "offset": 0.0},
  "variables": [
    {"path": "simulation.populations.p_x", "bounds": [0.0, 1.0]},
    {"path": "simulation.populations.p_y", "bounds": [0.0, 1.0]}
  ],
  "relations": [{
    "target": "simulation.populations.p_z", "constant": 1.0,
    "terms": {
      "simulation.populations.p_x": -1.0,
      "simulation.populations.p_y": -1.0
    }
  }]
}
```

В этом примере D/E/g остаются фиксированными, а третья населённость зависит от
двух независимых переменных. Это связь конкретного фита, а не общее требование
MaRS: его относительные веса сами по себе не обязаны иметь единичную сумму.

Для `dimension: "2d"` в `simulation` передаются `spin_model` от предыдущего
этапа и `context` с населённостями и временами релаксации. Гамильтониан при этом
фиксирован. При фактическом совместном подборе гамильтониана и кинетики существует
вариант `dimension: "2d_full"` с `hamiltonian`, `settings` и `context`.
Изменять вид модели относительно исходного фита нельзя.

`simulation.population_basis` задаёт базис начальных населённостей:
xyz/product/eigen/zfs/multiplet/zeeman, по умолчанию xyz. Он фиксирован для
контрольной COBYLA. В текущем 2D-контексте T1-переходы всегда в eigen, а потери
подуровней — в xyz, независимо от population_basis. Эти же правила использует
приватный симулятор проверки. ham_strain разрешён внутри hamiltonian/spin_model,
задан в Hz и в 2D-контекстном фите остаётся фиксированным.

Варьируемые пути допускаются только внутри `hamiltonian`, `populations`,
`context`, `rise_time_us` либо `calibration.scale/offset`. Элементы анизотропного
g задаются как `simulation.hamiltonian.g.0` и аналогично. Условия эксперимента,
точность сетки и оси оптимизатор не меняет. Не перечисленные величины фиксированы.
Список должен полностью соответствовать независимо варьировавшимся параметрам
исходной задачи; нельзя сузить его ради приёмки.

Все границы конечны; отключённое время `null` остаётся фиксированным. Линейные
связи задаются `relations` без исполняемого кода; циклы запрещены. Нарушающие
физические ограничения точки получают штраф и не могут стать лучшим результатом.
Сбой симулятора не маскируется под плохую точку.

Необязательный `constraints` хранит дополнительные границы зависимых параметров:
`[{"path":"simulation.context.p_z","bounds":[0.2,0.4]}]`. Они проверяются после
`relations` до симуляции, включая исходную точку; за пределами допустимой области
кандидат отклоняется. Это сохраняет выбранные границы третьей населённости при
её вычислении из суммы 1. Условия не добавляют независимых координат.
Старые снимки без `constraints` продолжают работать.

`calibration` хранит масштаб/смещение, уже использованные при формировании
переданного спектра. Если применяется `--alignment scale/affine`, его нельзя
одновременно дублировать соответствующим свободным калибровочным параметром.
Внутреннее нормирование MaRS fitter отключено (`norm_mode="none"`); неизменное
дополнительное масштабирование самой целевой функции MaRS не влияет на выбор точки.
Отчётные K вычисляются независимо в физических единицах сравнения.

## Запуск

Имена переменных ниже подставляются из текущей задачи. `N_FREE` включает реально
подобранные независимые параметры; правила подсчёта и форматы спектров — в FIT_CHECKS.
`K_MAX`, `DELTA_K_ABS`, `DELTA_K_REL` фиксируются до основного фита.

```bash
../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_refit_1d.py" --root "$PWD" \
  --slice "$SLICE_CSV" --fit "$FIT_NPZ" --parameters "$PARAMETERS_JSON" \
  --noise-window-ns 0 500 --n-parameters "$N_FREE" --max-k "$K_MAX" \
  --budget 500 --time-limit-seconds 300 \
  --improvement-atol "$DELTA_K_ABS" --improvement-rtol "$DELTA_K_REL" \
  --report "$NEW_REPORT_JSON"

../.mars_env/bin/python "/mnt/c/Users/kurga/OneDrive/Документы/YSDA/checks/check_refit_2d.py" --root "$PWD" \
  --data "$DATA_2D" --fit "$FIT_NPZ" --parameters "$PARAMETERS_JSON" \
  --noise-window-ns 0 500 --n-parameters "$N_FREE" --max-k "$K_MAX" \
  --budget 500 --time-limit-seconds 300 \
  --improvement-atol "$DELTA_K_ABS" --improvement-rtol "$DELTA_K_REL" \
  --report "$NEW_REPORT_JSON"
```

Для 2D сохраняется `--fit-time-offset-ns`, когда время симуляции отсчитывается от
собственного начала. Значение не является автоматически найденным временем лазера.

Скрипт для среза проверяет один набор данных. Если общие свободные параметры
подбирались одновременно по нескольким срезам, индивидуальная доводка не является
приёмкой совместного фита. Для проверки населённостей отдельного среза общие
параметры оставляют фиксированными согласно исходной постановке.

## Статусы

- Код 0, `passed`: качество относительно шума приемлемо и существенного улучшения
  в заданном проверочном бюджете не найдено.
- Код 1, `failed`: контроль существенно улучшил K или исходный K превышает допуск.
- Код 2, `diagnostic`: нет допуска приёмки относительно шума.
- Код 2, `inconclusive`: истёк лимит времени; проверка не завершена.
- Код 2, `invalid`: входы или параметры не согласуются со спектром, backend
  недоступен либо проверка сломалась. Это не основание принимать ответ.

Улучшенный результат служит доказательством необходимости продолжить основной
подбор. Он не заменяет автоматически исходный ответ агента и его записи.
