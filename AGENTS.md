## 1.2 Моделирование 1d спектров

Для готового среза начни с [короткой инструкции](instructions/fit-slice.md).
Подробный spectra-modeling нужен для смены этапа, команд проверок или правки кода.
Границы ищи signal_bounds.py, максимумы/минимумы — find_peaks.py по fit-slice;
X/Y/Z и a/e назначай сам. Пороговые края не подставляй вместо Z-пиков при оценке D и центра.
Начинай со срезов и оценивай согласие скриптами по loss-function.
Для всех трёх фитеров действует [общий контракт параметров](src/fit_utils/README.md):
агент сам выбирает границы и свободные/фиксированные параметры через JSON/CLI.
Рабочая конвенция: D != 0, 0 <= E/D < 1/3; при E != 0 знаки совпадают.
Прежний положительный диапазон старта D — 500–3000 МГц; знак выбирай по памятке.
До каждого запуска сохрани конфигурацию и новый
fit_id; пересмотр настроек создаёт новую версию, не меняет историю и приёмку.
1D-фит готов после основной `check_fit_perturbation_1d.py` и проверок комплектности; `check_refit_1d.py` — дополнительный контроль:
для основных проверок нужны код 0 и статус `passed`, новые JSON-отчёты и метрики в задаче.
Также обязательны наложение фита/эксперимента в SVG и проверка рисунка ниже.

## 1.3 Моделирование 2d спектров

Используй тот же модуль. Сначала параметры спинового гамильтониана из 1d,
затем населённости и их кинетики; соблюдай условия изменения параметров.
Для high-J доступны [2D-фитеры контекста](src/fit_utils/README_2D.md): TPE,
MaRS Cobyla и обе стадии; агент выбирает границы и vary только населённостей,
времён потерь, внутритриплетной релаксации и роста. Гамильтониан, уширения и
условия расчёта из 1D неизменны. До запуска сохрани контракт и новый fit_id;
явно задай время начала, не принимай 500 нс за время лазера.
Базис населённостей наследуется из 1D и выбирается агентом для нового fit_id;
T1 всегда eigen, потери подуровней всегда xyz. ham_strain наследуется и фиксирован.
2D-фит готов после основной `check_fit_perturbation_2d.py` и проверок комплектности; `check_refit_2d.py` — дополнительный контроль:
для основных проверок нужны код 0 и статус `passed`, новые JSON-отчёты и метрики в задаче.
Также обязателен один SVG с 6 кинетиками и 6 срезами по времени, с экспериментом
и моделью в каждой панели. Поля/времена выбирай по [fit-drawing](instructions/fit-drawing.md).

**Пирсон и контрольная модель — обязательный критерий 1D/2D-фита.**
Требуется знаковая корреляция `r >= 0.32`, затем `Q_original <= Q_control`
для единственного контроля `D'=-2D, E'=-E`. При меньшей корреляции или меньшем Q
контроля отвергни кандидат. Остальные параметры, базис/порядок населённостей,
масштаб, смещение, исходный делитель нормирования, сетки, окно и шум одинаковы;
контроль не дофитируй. Порог не меняй ради приёмки. Формат снимка и технический
допуск округления — [PERTURBATION_CHECKS](src/utils/PERTURBATION_CHECKS.md).
Полные команды из корня проекта; укажи фактические файлы, N_FREE и новые отчёты:

```bash
../.mars_env/bin/python "checks_tmp_for_hw2/check_fit_perturbation_1d.py" \
  --root "$PWD" --slice "$SLICE_CSV" --fit "$FIT_NPZ" --fit-key intensity \
  --parameters "$PARAMETERS_JSON" --noise-window-ns 0 500 \
  --n-parameters "$N_FREE" --alignment none --min-pearson 0.32 \
  --report "$NEW_PERTURBATION_REPORT_JSON"

../.mars_env/bin/python "checks_tmp_for_hw2/check_fit_perturbation_2d.py" \
  --root "$PWD" --data "$DATA_2D" --fit "$FIT_NPZ" --fit-key spectrum \
  --parameters "$PARAMETERS_JSON" --noise-window-ns 0 500 \
  --n-parameters "$N_FREE" --alignment none --min-pearson 0.32 \
  --report "$NEW_PERTURBATION_REPORT_JSON"
```

Ключ NPZ должен обозначать сохранённую модель в масштабе эксперимента; для
другого экспортёра задай его фактический ключ. При необходимости передай истинные
`--source-2d`, параметры операции среза, `--fit-window-ns` и `--fit-time-offset-ns`
из основного контроля. Окно шума 0–500 ns относится к текущим четырём измерениям.
Только код 0/`passed` и новый JSON подтверждают прохождение; сравнение не меняет
сохранённые D/E и не заменяет дополнительную MaRS Cobyla-доводку.

Для фитов обоих типов включай эти условия в «Готово, когда» до подбора.
Дополнительно обязателен `check_fit_table.py` по [fit-acceptance](instructions/fit-acceptance.md):
код 0, `passed`, новый JSON-отчёт; строка текущего спектра/фита в
`results/tables/1d-fit_results.csv` либо `2d-fit_results.csv`.
Для обоих типов целевая конвенция: |D| в [100,10000] МГц, 0 <= E/D < 1/3;
каждый g в [1,4];
px/py/pz в [0,1] с суммой 1 (допуск 1e-6); 0 < lw_Gs < 20 Гс.
Для 2D также все t_x, t_y, t_z, T_1 в [0.1,100000] мкс.
Старый check_fit_table пока требует D > 0: его согласование со знаковой конвенцией
относится к следующему этапу автоматизации. Не меняй знак/модуль результата ради проверки.
Все перечисленные параметры обязательны, конечны: без пустых значений, None,
NaN и ±Inf. Единицы и смысл ширины/времён фиксируй по fit-acceptance.
Проверки относятся к итоговым файлам и параметрам; после их изменения повтори
основной контроль D/E и проверки комплектности, включая рисунок. Пропуск, тайм-аут, ошибка или любой статус кроме `passed` означают, что
фит не готов. Несовместимость модели с проверкой исключением не является.

### 3.3. Скачивание файлов только с разрешением пользователя

В СПРАВКА загрузчик не запускай; используй метаданные и уже имеющиеся файлы.
Следующие правила скачивания применяются в режиме ЗАДАЧА.

- Любой новый файл из сети (PDF, HTML, архив, данные, код) получай только через
  `downloads-mcp__download_file(url, filename, purpose)`. Один вызов — один файл.
- В запросе скачивания укажи DOI, если он известен.
- Перед получением файла загрузчик показывает URL, цель и путь и запрашивает
  явное согласие пользователя. Согласие на предыдущий файл, молчание и просьба
  исследовать тему не разрешают новые скачивания. Каждый новый адрес
  перенаправления подтверждается отдельно.
- При отказе или недоступном подтверждении файл не скачивай и не ищи обходной путь.
  Параметра самостоятельного подтверждения у инструмента нет.
- Файлы сохраняются в `downloads/` без перезаписи существующих. Исходные загрузки
  доступны агенту для чтения; рабочие копии и результаты сохраняй в `results/`.
- Поиск записей, связей и аннотаций OpenAlex/Wikidata не требует подтверждения
  скачивания. HTML-страницу или полный текст статьи получай через загрузчик.
- Прямые `web_fetch` и `pdf_download` отключены. Не используй curl, wget,
  Python, установку пакетов, удалённые изображения или новые расширения для обхода.
- Оболочка агента запускает команды и все их дочерние процессы без сети,
  независимо от того, в какой папке лежит скрипт. Обычный терминал пользователя
  вне агента это ограничение не затрагивает.
- Для локальных правок используй защищённую оболочку. Запись разрешена в `src/`,
  `results/`, `tasks/`, `notes/`, `ontology/`, `reports/`, `memory/` и существующие
  `.obsidian/app.json`, `.obsidian/graph.json`. `diary.md` доступен только для
  чтения; дозапись — через `ai4science-mcp__append_diary(entry)`. Управляющие файлы,
  настройки и код обвязки из неё менять нельзя.
