## Модели и единицы

Два реализованных Hamiltonian:

- High-J: эффективный спин S=1,
  `H/h = (muB/h) B·g·S + S·D_tensor·S`.
- Moderate-J: два взаимодействующих электрона S1=S2=1/2,
  `H/h = (muB/h) B·(g1·S1 + g2·S2) + S1·(J I + D_tensor)·S2`.
  В этой реализации `g1,2 = g0 +/- delta_g/2`.

`D_tensor = diag(-D/3+E, -D/3-E, 2D/3)`, `|E| <= |D|/3`.
Для moderate-J это тензор межспинового взаимодействия. Положительный J в
соглашении `+J S1·S2` даёт триплет выше синглета для чистого обмена.
Не переносить J из соглашения ORCA `-2J S1·S2` без явного пересчёта.
В этих инструментах нет сверхтонкого взаимодействия и независимых ориентаций
разных тензоров: используется общая система осей, как в исходном notebook.

Единицы API: поля и FWHM ширины — T; частота и D/E/J — Hz; ось времени — s;
температура — K; углы общего ZYZ frame — радианы. Все `tau_*` и
`rise_time_us` задаются в **микросекундах**, а не в секундах.

### Базисы популяций и релаксации

XYZ — молекулярный триплетный базис, не лабораторные оси. Начальные веса
high-J имеют порядок `[Tx, Ty, Tz]`; moderate-J — `[S, Tx, Ty, Tz]`.
Потери из состояний задаются в этом базисе.

В текущей реализации high-J тепловые переходы задаются между соседями
`multiplet`-базиса. В moderate-J матрица спин-решёточной релаксации использует
**энергетически упорядоченный eigen-базис**: outer связывает 1↔2, 1↔3,
2↔4, 3↔4; inner добавляет 2↔3. MaRS температурно корректирует `thermal_rates`.

Не интерпретировать эту moderate-J матрицу как переходы между product-состояниями.
Исторически обсуждались `product`, `multiplet` и `eigen`; простой заменой ключа
нельзя сохранить физический смысл матрицы скоростей. При изменении модели
проверять базис, порядок состояний и соответствие переходов новым предположениям.

### Кинетика, начальные веса и нормировка

`null` для времени жизни означает **строго нулевую скорость**, число 0 как
время жизни недопустимо. Для конечного времени `k=1e6/tau_us` s^-1.
Очень большие конечные времена только приближают отсутствие релаксации.

Rising-поправка в этом workflow:
`S_out(B,t) = S(B,t) - S(B,0)*exp(-t/T_rise)`.
Это эмпирическая поправка выходного сигнала; она не является множителем
`1-exp(-t/T_rise)` и не добавляет канал рождения в master equation.
`S(B,0)` рассчитывается при истинном t=0 даже для обрезанной временной оси.

Режим `population_mode="notebook"` сохраняет исходные разные соглашения:
high-J 1D — minmax, high-J 2D — исходные веса; moderate-J 1D/2D — max.
Для прямого сравнения 1D и 2D использовать одинаковый `population_mode="raw"`,
одинаковые гамильтониан, настройки и полевую ось; выключить rise и задать
`null` для всех времён жизни. Отдельно учитывать описанные ниже проблемы solver.

`normalization="none"` по умолчанию сохраняет амплитуду. `maxabs` использует
один положительный максимум модуля для всего спектра/карты, сохраняя E/A-знаки.
Нельзя независимо нормировать каждый временной срез, если сравнивается кинетика.

## Интерфейс моделирования

Имена: `simulate_high_j_1d`, `simulate_moderate_j_1d`,
`simulate_high_j_2d`, `simulate_moderate_j_2d`,
`simulate_high_j_2d_full`, `simulate_moderate_j_2d_full`.

1D — стационарный спектр. 2D изменяет контекст при фиксированном переносимом
JSON `spin_model` из предыдущего вызова. 2D-full задаёт гамильтониан и контекст
явно; использует тот же численный алгоритм 2D, не запускает оптимизацию.

По умолчанию CPU, float64, частота 9.8e9 Hz, 80 K, `mesh=25` для обеих сеток,
гармоника 0. Частоту/температуру задавать по эксперименту; значения по умолчанию
не являются универсальными экспериментальными условиями. Гармоника 1 даёт
первую производную по полю. Один mesh управляет обеими сетками.

`device="auto"` выбирает доступный backend; недоступная явно запрошенная CUDA
возвращает ошибку. Для 2D со снимком `spin_model` device можно переопределить,
не меняя физические параметры. Для изменения mesh/гамильтониана использовать full.

Результаты: NPZ с `fields_T`, `times_s` для 2D, `raw_spectrum`, `spectrum`,
`metadata_json`; JSON и опциональный PNG. Карты имеют порядок **(time, field)**.
`raw_spectrum` уже включает rise, если он включён, но предшествует амплитудной
нормировке. Для больших карт возвращать пути, а не массивы в контекст LLM.

## Очистка экспериментальных 2D-карт

Имена: `inspect_epr_2d`, `import_epr_2d`, `correct_epr_2d_baseline`,
`denoise_epr_2d`, `clean_epr_2d`, `export_epr_2d`.

Рабочие массивы и NPZ: SI, порядок **(time, field)**. Notebook CSV:
первая строка — поле в G, первый столбец — время, внутри — сигнал.
Для времени без объявленных единиц явно указывать `source.time_unit`.
PKL содержит `datasets[name]` с `field_G`, `time`, `signal`; при нескольких
наборах явно выбрать dataset. Экспорт PKL совместим с этим форматом и
сохраняет acquisition `parameters`. NPZ загружается без pickle.

`field_bounds_T` и `time_bounds_s` задают **область полезного сигнала**.
Фон усредняется по временам **вне** этой области; полином поля фиттируется
по точкам **вне** полезного полевого интервала. Границы не обрезают карту.
`[trigger_time_s, null]` использует только более ранние времена для фона.

Коррекция сначала вычитает усреднённый фон, затем полином. Режим
`scaled_reference` масштабирует полином сильнейшего среза с опциональным
intensity shift; `independent` фиттирует срезы отдельно с начальными
коэффициентами соседнего среза. Внутренние координаты G/ns сохраняют
численную обусловленность notebook; публичные границы остаются в SI.

Фильтры MaRS: SVD, Gaussian, wavelet, median, combined. Адаптер сам переводит
карту в ожидаемый MaRS порядок (field, time) и возвращает (time, field).
Стартовые настройки notebook: SVD rank 10, Gaussian sigma_t=2/sigma_b=1
в отсчётах, db4/level 4/автоматический threshold, median kernel 3.
`combined` делает SVD, затем Gaussian с **половиной** заданных sigma.
Параметры выбирать по реальным данным и анализу удалённого сигнала;
настройки по умолчанию не гарантируют сохранение всех значимых особенностей.

Исходные файлы не перезаписываются. Сохраняются исправленная карта,
входной/удалённый сигнал, диагностические массивы, опции, история, SHA-256
источников и backend, версии. Фазировка, амплитудная нормировка и
интерполяция NaN автоматически не выполняются.

## Проверки и существенные ограничения

13 октября 2026 в целевом проекте прошли все 8 тестов очистки: восстановление
синтетического сигнала в обоих режимах baseline, совпадение пяти фильтров с
прямыми вызовами MaRS, порядок осей, pipeline, артефакты и CSV/NPZ/PKL round trips.
Байты bundled baseline совпадали с исходным helper notebook.

Для моделирования ранее прошли 8 тестов на CPU с mesh=4, согласно README:
прямое соответствие notebook, 1D/2D при нулевых скоростях, 2D/full,
rise, кэш и артефакты. Папку tests пользователь не сохранил в перенесённом
`src/mars_simulation`; не утверждать, что эти тесты можно запустить там сейчас.
Последняя проверка совместной регистрации показала 12 уникальных инструментов.

В исходном проекте обнаружена **ошибка broadcasting резонансного solver MaRS**:
в `res_field_algorithm.py`, `compute_error` перемножает интервалы [N,1,1]
и производные [N,4], получая [N,N,4]. Проверка `.any(dim=-1)` может принять
условие для другой ориентации. Это давало существенные сдвиги спектров и
чрезмерную память. Проверенная 14 октября строка установленного solver
по-прежнему содержит `(B_high - B_low) / 8 * (derivatives_high - derivatives_low)`;
повторного численного аудита backend в этот день не проводилось.

Процессная диагностическая подмена в старом исследовании улучшала ошибки
резонансов, но не была валидированным production исправлением. Агентские
инструменты используют установленный backend **без этой подмены**.
Сходимость по mesh и совпадение с notebook не доказывают правильность
резонансных полей или точность fitted parameters. Для количественной работы
нужен аудит solver на фактической версии, затем сходимость по сетке.
Исторические scripts mesh-исследования удалены при cleanup; README и результаты
сохранились. Не выдавать его старые команды за исполнимые без восстановления.

В текущем `AGENTS.md` осталась инструкция table checker из прежней задачи.
Файл `checks/check_tables.py` отсутствовал при предыдущей проверке. Эту
проверку не считать пройденной и не заменять молча тестами MaRS.
Решение несогласованности AGENTS.md требует отдельной актуализации, не
изменять этот файл как побочный эффект передачи контекста.
